# baton 1.0.4

**Stop your AI agent from re-reading your project every new session.**
baton 1.0.4 protects the edits you make to a handoff by hand. When you remove lines from `HANDOFF.md` in your editor, the dropped-lines warning no longer asks the AI to put them back — in a new session too, until the last committed version changes. Lines the AI drops itself are still reported. When the handoff is loaded, one line tells the AI that a person may have edited it, plus any problems your edit left because it skipped the save-time check. baton keeps only hashes for this, never the handoff text.
English overview: [README.md](https://github.com/sulabo/baton#readme) · homepage: https://sulabo.github.io/baton/

AI가 새 대화마다 프로젝트를 처음부터 다시 읽지 않게 하는 Claude Code·Codex 플러그인입니다.
사람이 직접 고친 인계서를 지키는 판입니다.

## 설치·업데이트

Claude Code 안에서:

```
/plugin marketplace add sulabo/baton
/plugin install baton@baton
```

이미 설치했다면 터미널에서 `claude plugin marketplace update baton` → `claude plugin update baton@baton`을 돌리고 창을 새로 엽니다. 열려 있던 창은 옛 훅을 계속 씁니다. Codex는 `codex plugin marketplace upgrade baton`.
필요한 것은 `git`과 `python3`뿐입니다. Codex(0.155 이상) 새 설치는 `codex plugin marketplace add sulabo/baton` → `codex plugin add baton@baton`.

## 1.0.4에서 바뀐 것

- **직접 고친 인계서를 지킵니다.** `HANDOFF.md`를 편집기로 고쳐 줄을 지우면, AI가 다음에 인계서를 저장할 때 "빠졌다, 되살려라" 경고를 받지 않습니다.
  - 전에는 사람이 지운 줄을 커밋하지 않았으면, AI가 그 경고를 보고 지운 줄을 되살릴 수 있었습니다.
  - baton은 AI가 저장한 판(그리고 AI 턴이 끝날 때의 판)을 기억합니다. 다음 프롬프트 때 파일이 그 판과 다르면, 그 사이에 없어진 줄을 사람이 지운 줄로 봅니다.
  - 새 대화에서도 그렇고, 마지막 커밋판이 바뀔 때(커밋·pull·checkout·reset)까지 갑니다. 지웠다가 되살린 줄은 기억에서 빠집니다.
  - AI가 스스로 지운 줄은 전처럼 알립니다.
- **인계서를 넣을 때 한 줄을 같이 넣습니다.** 사람이 고쳤을 수 있으니 고친 내용을 이어 쓰고 지운 줄은 되살리지 말라는 말, 그리고 저장 검사를 거치지 않아 남은 문제(크기·필수 절)입니다.
- **인계서 글은 남기지 않습니다.** 기억은 `~/.cache/baton/handoff-files/`에 해시만 둡니다(폴더 700, 파일 600, 30일 지나면 지움).

## 한계

- 다음 경우에는 사람이 지운 줄을 다시 알릴 수 있습니다(예전과 같은, 안전한 쪽).
  - AI가 일하는 턴 도중에 고친 것.
  - 작업 알림으로 시작한 턴 앞의 편집.
  - 고친 뒤 프롬프트 전에 같은 폴더의 다른 창이 턴을 끝내거나 Bash를 돌린 경우.
- 드물게 AI가 지운 줄을 놓칠 수 있습니다.
  - 다른 창의 AI가 인계서를 쓴 바로 그 순간에 프롬프트를 친 경우.
  - 중단(Esc)된 턴의, 훅이 보지 못한 쓰기(Codex `apply_patch` 등).
  - 턴 뒤에 끝난 백그라운드 작업의 쓰기.
- `BATON_HANDOFF_CHECK=off`면 꺼집니다.

## 검증

- 단위 테스트 744개 통과(4개 건너뜀). 새 테스트 15개가 리뷰에서 재현된 흐름을 고정합니다.
- 바꾼 줄을 하나씩 되돌려 테스트가 잡는지 확인했습니다.
- 독립 코드 리뷰 세 번(REQUEST CHANGES 두 번 → APPROVE WITH NITS → 지적 반영)을 거쳤습니다.
- 실제 사용으로는 아직 재지 않았습니다.
