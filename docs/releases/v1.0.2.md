# baton 1.0.2

**Stop your AI agent from re-reading your project every new session.**
baton 1.0.2 fixes what showed up in real use of 1.0.1. At a context threshold the agent is asked to save a handoff only at the end of a turn that did work, so a question or a read-only turn is never stopped (Claude Code). A `HANDOFF.md` written through a Bash command is checked like one written with the edit tools. Shrinking an over-long handoff is no longer blocked on every save. The concept-map notice shows at most once a day unless its count changes. A window left open on an older version says so once.
English overview: [README.md](https://github.com/sulabo/baton#readme) · homepage: https://sulabo.github.io/baton/

AI가 새 대화마다 프로젝트를 처음부터 다시 읽지 않게 하는 Claude Code·Codex 플러그인입니다.
1.0.1을 실제로 쓰다 나온 불편을 고친 판입니다.

## 설치·업데이트

Claude Code 안에서:

```
/plugin marketplace add sulabo/baton
/plugin install baton@baton
```

이미 설치했다면 터미널에서 `claude plugin marketplace update baton` → `claude plugin update baton@baton`을 돌리고 창을 새로 엽니다. 열려 있던 창은 옛 훅을 계속 씁니다. Codex는 `codex plugin marketplace upgrade baton`.
필요한 것은 `git`과 `python3`뿐입니다. Codex(0.155 이상) 새 설치는 `codex plugin marketplace add sulabo/baton` → `codex plugin add baton@baton`.

## 1.0.2에서 바뀐 것

- **질문만 한 턴에는 멈추지 않습니다**(Claude Code). 맥락이 25만·45만 토큰 문턱을 넘어도, 그 턴에 한 일이 없으면(질문하거나 읽기만 한 턴) 인계서를 쓰게 하지 않습니다. 그 문턱은 남겨 뒀다가 다음에 일한 턴 끝에 한 번 묻습니다. 1.0.1 기록을 다시 돌려 보니 막힘 10번 중 5번이 그런 턴이었습니다.
- **Bash로 쓴 인계서도 검사합니다.** python heredoc처럼 Bash 명령으로 `HANDOFF.md`를 쓰면, 그 명령이 인계서 파일 이름을 말했고 그 호출 중에 파일이 바뀐 경우에 저장 검사를 돌립니다. `git checkout`이나 다른 창이 바꾼 인계서는 검사하지 않습니다. 실사용에서 인계서 쓰기 약 74번이 Bash였고, 상한을 넘은 인계서가 9번 커밋됐습니다. 그래도 인계서는 편집 도구로 고치는 게 가장 좋습니다(Bash로 쓰면 쓴 뒤에야 검사됩니다).
- **긴 인계서를 줄여 가는 저장은 매번 막지 않습니다.** 직전보다 짧아졌으면 경고만 하고, 크기 때문에 막는 것은 한 턴에 한 번입니다. 몇 자(또는 몇 줄)를 더 줄여야 하는지와 가장 큰 절 두 개를 알려 줍니다.
- **개념 지도 알림은 하루에 한 번만 나옵니다.** 다시 볼 개념 수가 바뀌면 바로 나옵니다. `BATON_DRIFT_NOTICE=off`로 끕니다.
- **오래 열어 둔 창을 알려 줍니다**(Claude Code). 1.0.2 이후 판으로 연 창이 그 뒤 업데이트를 못 받았으면 대화마다 한 번 알립니다. 지금 1.0.1·베타로 열려 있는 창은 알리지 못하니, 업데이트한 뒤 창을 새로 열어 주세요.
- `/baton-doctor`가 플러그인 스킬을 가리는 같은 이름 개인 스킬(`~/.claude/skills/handoff`·`ontology`·`baton-setup`)을 찾아 줍니다.
- 작은 오류 둘을 고쳤습니다. 0건 가드가 `지적 1건: 정본 없음` 같은 줄에서 울리지 않고, 읽을 수 없는 `HANDOFF.md`에서 주입 훅이 오류로 끝나지 않습니다.

## 실제 대화로 확인한 것

출시 전에 연습 저장소에서 실제 Claude Code 대화 하나를 이어 가며 확인했습니다(2026-11-26, 맥락 문턱을 7만 토큰으로 낮춰서).

- 파일을 고친 뒤, 큰 파일을 읽기만 한 턴은 맥락이 문턱을 넘었는데도 멈추지 않았습니다.
- 그다음 파일을 고친 턴 끝에서 한 번 인계서를 쓰게 했고, 같은 문턱으로 다시 묻지는 않았습니다.
- Bash(python)로 인계서에 홈 폴더 경로를 넣자 그 호출 뒤에 바로 문제를 알렸습니다.
- 대화 밖에서 바꾼 인계서를 `cat`으로 읽기만 할 때는 아무 말도 하지 않았습니다.
- 인계서를 쓰고 실패로 끝난 Bash 호출 뒤에도 문제를 알렸고, AI가 그 알림을 받아 답했습니다.

대화 하나로 한 시험이고, 모델은 Sonnet 5.5였습니다.

## 아직 확인하지 못한 것

- Codex에서는 실패로 끝난 Bash 호출을 검사하지 않습니다. Codex 훅에는 그 이벤트가 없어서 Codex용 훅 파일에서 뺐습니다. 훅 파일이 바뀌어서 Codex가 훅을 다시 신뢰해 달라고 할 수 있습니다.
- 실사용에서 토큰이 줄었는지는 아직 모릅니다.

## 알려진 한계

- 수치는 만든 사람 한 명의 기록에서 나왔습니다.
- 인계서 파일 이름을 말하지 않는 스크립트가 쓴 인계서는 검사하지 않습니다. 한 Bash 호출 안에서 쓰고 커밋하면 커밋한 뒤에야 검사됩니다.
- Bash 명령마다 검사 훅이 하나 더 돌아, 한 번에 약 0.04초가 더 듭니다.
- 인계서가 없는 저장소에서도 `HANDOFF.md`를 새로 만듭니다(이 대화에서 한 일이 있고 맥락이 문턱을 넘을 때, 또는 파일을 3개 이상 고쳤을 때). 원하지 않으면 `BATON_HANDOFF_AUTO=off`(쓰지 않고 알리기만). 맥락 문턱만 끄려면 `BATON_SPLIT_NOTICE=off`.
- 자동 갱신, 맥락 문턱 인계서 갱신, 저장할 때 자동 검사는 Claude Code에서만 돕니다.
- 인계서를 넣는 말은 프롬프트 어디에 있어도 걸립니다. 붙여 넣은 글 속의 "이어서"에도 인계서가 들어갑니다.
- 플러그인이 띄어쓰기가 있는 경로에 설치되면 스킬이 스크립트를 실행하지 못할 수 있습니다(기본 설치 경로에는 없습니다).
- 인계서 검사기는 일부 비밀값 형식(`postgres://user:pw@host`, `npm_`·`hf_` 토큰, JWT가 아닌 Bearer 값)을 놓칩니다.
- `/rewind` 뒤에는 인계서가 맥락에 있다고 보고 다시 넣지 않습니다.
