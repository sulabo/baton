## 문제

새 대화는 아무것도 모릅니다. 그래서 AI는 README, 메모, 지난 인계서, 그 주변 파일부터 다시 읽습니다. 만든 사람의 기록에서 "어디까지 했지?" 같은 진행 질문으로 시작한 대화 42개 중 41개가 처음 다섯 번의 호출 안에 `HANDOFF.md`를 다시 열었습니다. 호출은 AI가 모델에 한 번 요청하는 것입니다. 거의 매번 다시 연 셈입니다. 읽은 것은 맥락(모델이 답할 때마다 함께 읽는 글 전체)에 남고, 맥락은 대화가 끝날 때까지 계속 커집니다. 게다가 메모는 낡습니다. AI는 코드와 이미 달라진 인계서나 문서를 그대로 믿습니다.

## baton이 하는 일

두 가지를 합니다.

### 1. 인계서: 지난 대화를 한 장으로

인계서(`HANDOFF.md`)는 대화를 끝낼 때 남기는 한 장짜리 작업 메모입니다. 작업 하나를 마치면 "핸드오프 작성해줘"라고 합니다. AI가 `HANDOFF.md`를 쓰고, 훅이 저장되는 순간 검사합니다. Claude Code에서는 하던 일이 끝나면 baton이 AI에게 인계서를 갱신하라고도 합니다(아래 "작업이 끝나면 갱신합니다"). 다음 대화에서 "어디까지 했지?"라고 물으면 훅이 인계서를 맥락에 넣어 줍니다. 얼마나 오래된 인계서인지 알려 주는 한 줄도 함께 붙습니다. AI는 파일을 찾아 열 필요가 없습니다.

**실제 화면.** 데모 저장소에서 11일 전에 쓴 인계서 뒤로 커밋이 3개 들어온 상태입니다. AI가 받는 처음 몇 줄은 이렇습니다(실제 출력).

```
[baton] 아래는 이 저장소 HANDOFF.md의 전문이다(프롬프트가 인계·진행 상황을 가리켜 자동 주입). 파일을 다시 열 필요 없다. 다만 인계서는 작성 시점의 기록이다 — 사실이 아니라 가설로 읽고, 다음 행동이 기대는 주장 한두 개만 git·파일로 확인한 뒤 이어서 진행한다.
[baton] 이 인계서는 2026-11-11(11일 전, 첫 줄 작성일) 기준이다. 그 뒤 커밋 3개는 인계서에 없다 — `git log --oneline -3 -- .`부터 본다. 11일 지났다 — 다음 행동이 아직 유효한지부터 확인한다.

# Session Handoff (작성: 2026-11-11)
```

저장한 인계서에 문제가 있으면 AI에게 돌려줘 고치게 합니다(실제 출력. 찾은 값 자체는 다시 출력하지 않습니다).

```
[baton] 방금 쓴 HANDOFF.md에 인계서 검사 문제가 있다. 고친 뒤 다시 저장한다:
- 6줄: API 토큰 의심 값 — 지우거나 일반 표기(~/, <키>)로 바꾼다
- 6줄: 비밀번호·키 대입 의심 값 — 지우거나 일반 표기(~/, <키>)로 바꾼다
- 7줄: 홈 절대경로 의심 값 — 지우거나 일반 표기(~/, <키>)로 바꾼다
- 9,277자 — 상한 8,700자를 넘는다(넘친 뒤쪽은 다음 세션에 주입되지 않는다)
```

자세히는 이렇습니다.

- **저장하면 검사합니다.** 길이(200줄·8,700자), 필수 8절, 20줄 넘는 코드 블록, 전체 diff, 비밀값, 홈 절대경로를 봅니다. `/baton-setup`에서 고른 개인 자료 단어(이름·이메일 등)도 막습니다. 문제가 있으면 AI에게 돌려줍니다. "확인된 사실과 결정" 절의 줄에 `[V]`(직접 확인함)·`[?]`(기억·추정) 표시가 없으면 막지는 않고 경고만 합니다. 손으로 돌리려면 `python3 lib/handoff_check.py HANDOFF.md`.
- **빠진 줄을 알립니다.** 저장할 때 검사기는 파일을 마지막 커밋판(`git show HEAD:HANDOFF.md`)과 비교해 없어진 줄을 보여 줍니다. "실패한 접근법", "승격 후보", "기각됨" 절은 대화를 넘어 남겨 두는 절이라 빠진 줄을 모두 보여 줍니다. "확인된 사실과 결정", "남은 리스크와 다음 행동" 절은 끝난 일을 지우는 게 보통이라, "소유자"·"결정"·"금지" 같은 결정·제약 표지가 있는 줄만 봅니다. 인계서의 다른 곳이나 `DECISIONS.md`로 옮긴 줄은 빠진 것으로 치지 않습니다. 막지 않고 경고만 하고, `HANDOFF.md`를 아직 커밋하지 않았으면 아무 말도 하지 않습니다. 이 규칙은 저장소 하나의 인계서 이력으로 맞췄습니다. 그 표본 20줄에서 알린 줄의 약 20%는 잘못 알린 것이었습니다.
- **물어볼 때만 넣습니다.** 프롬프트에 이어 가자는 말이 있을 때만 넣습니다. 기본 말은 "이어서", "어디까지", "인계", "handoff", 그리고 "where were we" 같은 영어 구입니다. 그런 말이 없으면 인계서는 넣지 않습니다. 말이 프롬프트 어딘가에 글자 그대로 들어 있기만 하면 걸립니다. 그래서 "인계"가 들어간 작업 요청에도 들어갑니다.
- **한 번에 다 들어갑니다.** 검사를 통과한 인계서는 잘리지 않고 통째로 들어갑니다. 머리말, 신선도 줄, 필독 줄까지 합친 훅 출력 전체가 Claude Code의 훅 출력 상한(10,000자) 안에 들어옵니다. 상한을 넘으면 Claude Code는 글을 파일로 빼고 앞부분 미리보기만 넘깁니다.
- **한 대화에 한 번만 넣습니다.** 같은 인계서는 한 번만 넣습니다. 그 뒤 `HANDOFF.md`가 바뀌었거나 대화가 압축됐을 때만 다시 넣습니다. 압축(compaction)은 긴 대화를 요약으로 줄이는 일입니다. 다른 대화·서브에이전트(AI가 일을 나눠 맡기는 보조 AI)가 보낸 메시지(`<agent-message>`·`<cross-session-message>`)와 작업 알림(`<task-notification>`)에는 넣지 않습니다. 사람이 부른 게 아니기 때문입니다.
- **신선도 한 줄을 붙입니다.** 작성일은 인계서 첫 3줄의 날짜에서 읽습니다. 없으면 `HANDOFF.md`를 마지막으로 커밋한 날을 씁니다. 커밋 수는 `HANDOFF.md`를 마지막으로 커밋한 뒤 이 폴더에 들어온 커밋 수입니다. 7일이 지났으면 다음 행동이 아직 맞는지부터 보라고 적습니다. 셀 수 없을 때(인계서를 커밋하지 않고 고치는 중, 얕은 복제, git이 3초 안에 안 끝남)는 "없다"가 아니라 못 셌다고 적습니다.
- **필독 표시.** "관련 파일·심볼" 절에서 다음 대화가 행동 전에 꼭 읽어야 할 항목 최대 3개의 경로 뒤에 `(필독)`(영어로는 `(must read)`)을 붙입니다. 인계서를 넣을 때 그 항목들을 신선도 줄 바로 뒤에 한 줄로 한 번 더 넣습니다. 인계서가 잘려도 그 줄은 남습니다. 3개를 넘게 붙이면 검사기가 경고하고, 이 줄 길이도 8,700자에 셉니다.
- **작업이 끝나면 갱신합니다(Claude Code).** baton은 이 대화에서 마지막으로 인계서를 쓴 뒤(쓴 적이 없으면 대화 시작부터) 고친 파일 수를 셉니다. 3개(`BATON_HANDOFF_NUDGE_FILES`)가 되면 Stop 훅이 대화에 한 번 `HANDOFF.md`를 갱신하라고 AI에게 말합니다. Stop 훅은 AI가 답을 마칠 때 도는 훅이고, 이때 AI는 답을 끝내지 않고 이어서 인계서를 씁니다. AI는 기억으로 새로 쓰지 않고 지금 파일에서 시작해, 아직 참인 줄은 그대로 옮깁니다. 검사기를 돌리고, 승격 검토는 건너뛰고, 커밋하지 않고, 갱신했다는 것을 한 줄로 알립니다. 기본으로 켜져 있습니다. `BATON_HANDOFF_AUTO=off`면 예전처럼 사용자에게 짧은 제안만 하고, 쓸지는 사람이 정합니다. `BATON_HANDOFF_NUDGE=off`는 둘 다 끕니다. `HANDOFF_트랙.md`처럼 이름 붙은 인계서를 써도 쓴 것으로 칩니다. 검사와 주입은 `HANDOFF.md`만 합니다.
- **알림.** 맥락이 대화 첫 호출 때 크기의 2배를 넘을 때, 그리고 3배를 넘을 때 한 번씩 알립니다. 인계서를 쓰고 새로 시작하라는 알림입니다.
- **`/promote`** 는 여러 날 인계서에서 살아남은 제약을 `DECISIONS.md`(결정 기록) 후보로 보여 줍니다. **결정은 대신 쓰지 않습니다.** 왜 그렇게 정했는지, 무엇을 버렸는지는 결정한 사람만 압니다. 추측으로 채우면 가장 중요한 줄이 거짓이 됩니다.

### 2. 개념 지도: 프로젝트에서 바뀐 곳

"개념 지도 만들어줘"라고 하면 `driftmap` 스킬이 프로젝트의 핵심 개념 8–12개를 골라 `CONCEPTS.md`를 씁니다. 개념은 게임의 점수 규칙이나 로그인 흐름 같은 것입니다. 개념마다 관련 결정, 코드 파일, 문서, 그리고 마지막으로 확인한 커밋을 적습니다. 그 뒤로는 걸린 파일이 바뀐 개념만 다시 봅니다. 결정 기록·코드·문서가 서로 다른 말을 하는 곳도 적어 둡니다.

**개념 색인을 대화마다 한 번 넣습니다.** 저장소에 `CONCEPTS.md`가 있으면, 대화에서 처음 친 프롬프트에 그 색인을 함께 넣습니다. 이어 가자는 말이 없어도 넣습니다. 개념마다 한 줄씩, 이름과 제목의 "—" 뒤 설명(있을 때만), 주요 파일 최대 세 개를 적습니다. AI는 이 목록에서 고릅니다. 프롬프트의 말을 개념 제목에 맞추지는 않습니다. 사람이 일을 부르는 말과 개념 이름은 대개 다르기 때문입니다.

- **비용.** 대화마다 최대 1,500자이고, 넣은 뒤로는 매 턴 맥락에 남습니다. 기본으로 켜져 있고, `BATON_CONCEPT_INDEX=off`로 끕니다.
- **언제.** 대화마다 한 번, 그리고 압축 뒤에 다시 넣습니다. 다른 대화의 메시지와 작업 알림에는 넣지 않습니다. 대화별 기억을 남길 수 없으면(대화 id가 없거나 캐시에 못 씀) 아예 넣지 않습니다.
- **인계서와 함께일 때.** 같은 프롬프트에 인계서가 들어가면 색인은 그 뒤에 붙고 자리를 양보합니다. 검사를 통과한 인계서는 색인 때문에 잘리지 않습니다. 자리가 모자라면 설명, 첫 파일 뒤의 파일, 뒤쪽 개념 순서로 줄이고, 몇 개를 뺐는지 마지막 줄에 적습니다.
- **효과.** 아직 재는 중입니다. 24번 돌린 시험(일상어 질문 4개를 색인이 있을 때와 없을 때 3번씩)에서 질문 2개는 나았고, 2개는 더 나빴습니다.

같은 데모 저장소에서, 이어 가자는 말이 없는 첫 프롬프트에 들어간 색인입니다(실제 출력).

```
[baton] 이 저장소 개념 지도(CONCEPTS.md) 색인이다. 작업에 맞는 개념의 파일부터 연다. 개념은 탐색 앵커다 — 실제 동작은 코드로 확인한다. 자세한 근거는 CONCEPTS.md의 그 절에.
1. 목숨 — 시작할 때 목숨 수 · 파일: src/lives.ts
2. 점수 — 코인 하나당 점수 · 파일: src/score.ts
3. 레벨 — 레벨 목록, 아직 비어 있음 · 파일: src/levels.ts
```

**실제 화면.** 같은 데모 저장소에서 커밋 하나가 `src/lives.ts`를 바꿨습니다. 다음 대화는 한 줄로 시작하고, `/drift`는 다시 볼 개념을 보여 줍니다(실제 출력).

```
[baton] 개념 지도에서 다시 확인할 개념이 2개 있어요(그대로인 개념 1개). 자세히 보려면 /drift
```

```
#    개념                 상태       판정
---- ---------------------- ------------ ------------------------------
1    목숨                 일치       재확인 필요 — 커밋 1건
2    점수                 일치       신선
3    레벨                 미구현    재확인 필요 — 기준 없음

요약: 재확인 2 · 신선 1 · 규칙 개념 0
```

- 1번: 확인한 커밋 뒤에 걸린 파일이 바뀌었습니다.
- 2번: 바뀐 게 없어서 신선으로 표시되고, 다시 볼 필요가 없습니다.
- 3번: 한 번도 확인하지 않아 기준이 없습니다. 신선으로 세지 않고 따로 냅니다. 숫자를 못 셌을 때 0으로 보이지 않게 따로 표시합니다.
- 규칙 개념은 걸린 파일이 없는 개념입니다. 결정 기록에만 있는 규칙 같은 것입니다.

<details>
<summary><strong>지도는 무엇으로 신선을 정하나</strong></summary>

어긋남이 늘 낡은 문서인 것은 아닙니다. 정해 놓고 아직 만들지 않은 결정일 수도 있습니다. 문서끼리만 비교하면 맞는 문서를 "고치게" 됩니다. 그래서 개념마다 결정 기록·코드·문서 세 곳을 대조합니다.

개념마다 메타 줄 하나를 남깁니다.

```
- **메타**: 상태=일치 · 확인=2026-11-20(`9cd1928`) · 파일=`src/lives.ts` · 이웃=개념 2(전제) · 문서=`docs/guide.md`
```

차례로 상태, 확인한 커밋(`9cd1928`), 근거 코드 파일, 이웃 개념, 설명 문서입니다. 상태 `일치`는 결정·코드·문서가 맞는다는 뜻이고, 상태 말은 정해진 여덟 개 중에서만 고릅니다. 영어 지도는 같은 줄을 영어 키로 쓰고, baton은 둘 다 읽습니다([언어](#언어)). baton은 신선한지를 판단하지 않고 커밋을 셉니다. 그 파일들(코드·문서)에 `9cd1928` 뒤 커밋이 없으면 그 개념은 신선하고, 다시 볼 필요가 없습니다. 문서만 바뀐 경우도 따로 재확인으로 알립니다.

판정은 아홉 가지이고, 그중 다섯은 "모른다"의 종류입니다.

| 판정 | 뜻 |
|---|---|
| 신선 | 확인 이후 커밋이 없습니다. 다시 읽지 않습니다 |
| 재확인 필요 — 커밋 N건 | 파일이 바뀌었습니다 |
| 재확인 필요 — 기준 없음 | 확인 시점이 안 적혀 있습니다 |
| 재확인 필요 — 기준 소실 | 그 커밋이 이 저장소에 없습니다(squash된 브랜치의 커밋을 새 클론에서 볼 때 등) |
| 재확인 필요 — 기준이 현재 이력 밖 | 커밋은 있는데 지금 HEAD의 조상이 아닙니다(squash·rebase 뒤 남은 옛 커밋, 다른 가지, cherry-pick 원본) |
| 재확인 필요 — 경로 소실 | 파일이 없습니다(여럿 중 하나만 없어도) |
| 재확인 필요 — 미추적 | 중첩 저장소입니다 |
| 재확인 필요 — 문서 커밋 N건 · 재확인 필요 — 문서 경로 소실 N개 | 코드는 그대로인데 `문서=`에 적은 파일만 바뀌었거나 없어졌습니다 |
| 규칙 개념 — 결정 변동으로만 추적 | 파일이 없는 규칙 개념입니다. 결정 기록의 변동으로만 봅니다. 적어 둔 커밋이 소실·이력 밖이면 결정 변동도 셀 수 없어 재확인으로 올라갑니다. 해시가 미상인 규칙 개념은 알림을 내지 않습니다. 처음 만든 지도에서는 흔한 상태라, 매 대화 울리면 무시당하기 때문입니다. `/drift` 표에는 `(기준 없음 — 문서 못 봄)`으로 보입니다 |

확인 뒤 새 결정이 `관련:` 줄(영어로는 `Related:`)로 가리킨 개념도 재확인 대상이 됩니다.

**`파일`에는 지침 파일을 넣지 않습니다.** `AGENTS.md`·`DECISIONS.md` 같은 파일은 거의 매일 바뀝니다. 근거 목록에 있으면 내용이 가만히 있어도 개념이 늘 재확인 대상이 됩니다. 결정 쪽 변동은 따로 봅니다.

### 내 기록으로 맞추기 (선택, 한 번)

기본 문턱은 만든 사람의 기록으로 정했습니다. `/baton-setup`은 같은 방법을 **내 기록**에 다시 돌려 제안합니다(Codex에서는 "baton 설정해줘"로 스킬을 부릅니다). 고르기 전에는 아무것도 바꾸지 않습니다.

- **읽는 것**: 이 저장소 최상위에서 연 Claude Code 대화 기록(`~/.claude/projects`), git 작성자, 추적 파일과 무시되지 않은 미추적 파일, 다른 프로젝트 대화 기록의 작업 폴더 이름(프로젝트 이름 후보용), `HANDOFF.md`·`DECISIONS.md`·`CONCEPTS.md`. Codex 대화는 아직 세지 않습니다.
- **제안하는 것**: 새로 시작하라는 알림의 문턱(맥락이 첫 호출의 몇 배일 때), 인계서 자동 갱신·제안 문턱(파일 몇 개 고친 뒤), 인계서를 넣을 말 추가, 출력 언어(`BATON_LANG`, 지난 프롬프트 중 한글이 든 비율로), 인계서 검사가 막을 **개인 자료 목록**(내 이름·이메일·다른 프로젝트 이름 후보 중 내가 고른 것). 대화가 10개 미만이면 기본값을 그대로 권합니다.
- **쓰는 것**: 고른 값만 `~/.config/baton/config.json`(`XDG_CONFIG_HOME`이 있으면 그 아래)에 씁니다. 파일 권한은 600이고, 저장소별 절과 전역 절이 있습니다.
- **개인 자료가 남는 곳**: 스킬로 돌리면 스캔 출력(개인 자료 후보)과 apply 명령줄이 AI 맥락과 Claude Code 대화 기록에 남습니다. 원하지 않으면 단어를 저장소 밖 파일에 적어 `--private-terms-file`로 넘기거나, 대화 밖 터미널에서 직접 돌립니다.
- **우선순위**: 실제 환경변수 > 저장소 절 > 전역 절 > 기본값. 지금 적용된 값은 `python3 lib/config.py`로 봅니다.

## 빠른 시작

1. Claude Code 안에서 설치합니다.

   ```
   /plugin marketplace add sulabo/baton
   /plugin install baton@baton
   ```

   필요한 것은 `git`과 `python3`뿐입니다. 터미널에서는 `claude plugin marketplace add sulabo/baton && claude plugin install baton@baton`.

## 언어

baton은 메시지를 한국어나 영어로 냅니다. 이 설정은 메시지만 바꿉니다. 파일은 두 언어 모두 읽습니다.

**설정.** `BATON_LANG`에 `ko`, `en`, `auto` 중 하나를 줍니다. baton은 아래 순서로 보고, 처음 값이 있는 곳을 씁니다.

1. 환경변수 `BATON_LANG`
2. 설정 파일(`~/.config/baton/config.json`, `/baton-setup`이 씁니다)의 저장소 절에 있는 `BATON_LANG`
3. 같은 파일의 전역 절에 있는 `BATON_LANG`
4. 로캘(컴퓨터의 언어·지역 설정): `LC_ALL`, `LC_MESSAGES`, `LANG` 중 처음으로 값이 있는 것. 값이 `ko` 하나이거나 `ko` 뒤에 `_`, `.`, `@`, `-`가 오면(예: `ko_KR.UTF-8`) 한국어, 아니면 영어입니다.
5. macOS에서 위 세 변수가 모두 비어 있을 때(예: 터미널이 아니라 앱에서 Claude Code를 열었을 때): 시스템 언어 목록(`AppleLanguages`)의 첫 항목을 같은 규칙으로 봅니다.
6. 영어

`auto`나 `ko`·`en`이 아닌 값은 "로캘을 따른다"는 뜻입니다. 비어 있는 `BATON_LANG`은 설정하지 않은 것으로 봅니다. `/baton-setup`은 지난 프롬프트 중 한글이 든 것을 세어 `ko`나 `en`을 제안하고, 고르기 전에는 아무것도 쓰지 않습니다. `/baton-doctor`는 지금 언어와 그 값이 어디서 왔는지 보여 줍니다.

**두 언어의 파일 형식.** 설정과 상관없이 baton은 파일의 한국어 형식과 영어 형식을 모두 읽습니다. 한 파일 안에서는 한 형식만 씁니다.

`HANDOFF.md` 절 제목(템플릿은 [`skills/baton/SKILL.md`](../skills/baton/SKILL.md)에 있습니다):

| 한국어 | 영어 |
|---|---|
| `# Session Handoff (작성: YYYY-MM-DD)` | `# Session Handoff (written: YYYY-MM-DD)` |
| `## 목표와 완료 조건` | `## Goal and done criteria` |
| `## 확인된 사실과 결정` | `## Verified facts and decisions` |
| `## 관련 파일·심볼` | `## Files and symbols` |
| `## 이미 한 변경` | `## Changes made` |
| `## 실패한 접근법 (다시 시도 금지)` | `## Failed approaches (do not retry)` |
| `## 검증 증거` | `## Verification evidence` |
| `## 남은 리스크와 다음 행동` | `## Risks and next actions` |
| `## 승격 후보 (DECISIONS.md로 올릴 것)` | `## Promotion candidates (to DECISIONS.md)` |
| `### 기각됨 (다시 올리지 않는다)` | `### Rejected (do not raise again)` |
| `(필독)` | `(must read)` |

`CONCEPTS.md` 메타 줄:

| 한국어 지도 | 영어 지도 |
|---|---|
| `- **메타**:` | `- **Meta**:` |
| `상태=` | `status=` |
| `확인=` (모르면 `확인=미상`) | `checked=` (`checked=unknown`) |
| `파일=` (규칙 개념은 `파일=없음(규칙 개념)`) | `files=` (`files=none(rule concept)`) |
| `이웃=개념 2(전제)` | `neighbors=Concept 2(premise)` |
| `문서=` (문서가 없으면 `문서=없음`) | `docs=` (`docs=none`) |
| `별칭=` | `aliases=` |

상태 말(정해진 여덟 개):

| 한국어 지도 | 영어 지도 |
|---|---|

## 다른 도구와 비교

다른 도구의 내용은 각 도구의 공식 문서와 README를 2026-11-21·22에 읽고 적었습니다.[^reviewed]

| | baton | [claude-mem](https://github.com/thedotmack/claude-mem) | Claude Code 기본 기능(`CLAUDE.md`, auto memory, `/compact`, `/resume`) | [Basic Memory](https://github.com/basicmachines-co/basic-memory) |
|---|---|---|---|---|
| 하는 일 | 검사한 짧은 인계서를 다음 대화에 넘기고, 바뀐 개념을 알린다 | AI가 한 일을 대화를 넘어 기억한다 | 지침과 대화를 이어 간다 | AI가 읽고 쓰는 마크다운 지식 저장소 |
| 기록은 누가 쓰나 | 요청하면 AI가 `HANDOFF.md`·`CONCEPTS.md` 초안을 쓴다. 하던 일이 끝나면 AI가 `HANDOFF.md`를 갱신한다(Claude Code). 결정은 사람이 쓴다 | 훅이 도구 호출을 모으고, 두 번째 AI가 관찰과 대화 요약을 쓴다 | `CLAUDE.md`는 사람이, auto memory는 Claude가 쓴다. `/compact`가 요약을 쓴다 | AI가 MCP 도구로 쓴다. 파일은 평범한 마크다운 |
| 새 대화가 받는 것 | 첫 프롬프트: 개념 색인 한 번(1,500자 이하). 이어 가자고 하면: 인계서 한 번, 신선도 한 줄과 함께 | 지난 작업의 짧은 목록. 자세한 것은 필요할 때 검색 | 매번 `CLAUDE.md`, `MEMORY.md` 앞 200줄 또는 25KB, `--resume`이면 마지막 압축 요약과 그 뒤 메시지 | MCP로 찾아본 것(시작 시 동작은 확인하지 않음) |
| 어디에 두나 | 저장소 안 평범한 파일, 그리고 로컬 로그 | `~/.claude-mem` 아래 SQLite·FTS5·Chroma | 프로젝트 안 파일과 `~/.claude` 아래 | 머리 정보(frontmatter)와 `[[위키링크]]`가 있는 마크다운, SQLite 색인 |
| 라이선스 | MIT | Apache-2.0 | Claude Code에 포함 | AGPL-3.0 |

우리가 살펴본 도구 중에는 아래를 문서로 밝힌 곳이 없었습니다. baton이 채우려는 자리입니다. 놓친 도구가 있으면 이슈로 알려 주세요.

- 이어 가자는 프롬프트가 오면 인계서를 자동으로 맥락에 넣는 것. 한 대화에 한 번만 넣고, 서브에이전트·다른 대화의 메시지에는 넣지 않습니다.
- 저장할 때 규칙으로 하는 인계서 검사(크기·필수 절·비밀값·홈 경로·개인 자료 단어).
- 개념마다 마지막으로 확인한 커밋을 적어, 바뀌지 않은 개념은 다시 읽지 않는 것. 그리고 결정 기록·코드·문서가 어긋난 곳 표시.

인계서가 낡았는지 보는 쪽으로 가장 가까운 것은 [claude-handoff](https://github.com/willseltzer/claude-handoff)입니다. 이 도구의 `/handoff:resume` 명령은 AI에게 `git status`·`git log`를 돌려 인계서 뒤에 커밋이 있었는지 보라고 합니다. baton은 그 커밋 수를 AI가 읽기 전에 훅이 세서, 처음 몇 줄에 넣어 둡니다.

도구마다 하는 일이 다르고, 함께 쓸 수 있습니다. `/compact`·`/resume`은 한 대화를 이어 가고, baton은 새 대화에 짧은 인계서를 건넵니다. 아무것도 쓰지 않고 지난 대화를 자동으로 떠올리고 싶다면 claude-mem이 맞습니다.

## 지금까지 잰 것

**모든 수치는 만든 사람 한 명이 자기 저장소에서 쓴 기록입니다.** 수치마다 기간과 범위가 다릅니다. 다시 재는 명령과 출처는 [CHANGELOG](../CHANGELOG.md)와 [docs/research/LOOP_PLAN.md](research/LOOP_PLAN.md)에 있습니다. 토큰은 모델이 읽고 쓰는 글의 단위이고, 비용은 토큰 수로 매겨집니다.

- **인계서를 다시 여는 일은 줄었습니다(설치 뒤 표본 11개).** 진행 상황을 묻는 말로 시작한 대화에서, AI가 처음 다섯 번의 호출 안에 `HANDOFF.md`를 다시 연 경우를 셌습니다. 설치 전에는 **42개 중 41개**(2026-08-31–10-04, 그중 3개는 일부만 읽음)로 거의 매번이었습니다. 설치 뒤에는 **11개 중 3개**(10-19–11-20, 그중 2개는 일부만 읽음)였습니다. 다만 11개는 방향을 보여 줄 뿐, 효과의 크기를 말하기에는 적습니다.
- **같은 조건의 실험에서, 진행 상황 질문은 입력 토큰이 40–54% 줄었습니다.** 스냅샷 실험은 저장소 3곳에서 조건마다 3–5번 돌렸고, 저장소마다 같은 프롬프트를 썼습니다. 반대로 한 저장소(5번)에서 인계서와 무관한 작업에 인계서를 넣으면 **11% 늘었습니다.** 그래서 물어볼 때만 넣습니다.
- **실제 사용에서는 아직 토큰이 줄지 않았습니다.** 설치 뒤 대화의 첫 호출들이 오히려 더 들었습니다. 같은 기간 다른 플러그인과 지침도 커져서, 두 효과를 떼어 내지 못했습니다. 원인 하나는 baton 쪽에 있었습니다. 2026-10-04부터 11-19까지의 사용 로그를 보니 같은 인계서가 거듭 들어갔습니다. **대화 39개에 269번 넣었는데, 대화 첫 프롬프트에 들어간 것은 32번뿐**이었습니다([LOOP_PLAN](research/LOOP_PLAN.md)).[^count] 한 대화에 한 번만 넣는 규칙은 이것을 고치려는 것입니다. 효과는 아직 재지 않았습니다.
- **개념 색인의 비용과 효과는 아직 확인되지 않았습니다.** 24번 돌린 시험(일상어 질문 4개 × 3번 × 색인 있음·없음, 격리 환경)에서, 맞는 파일을 처음 겨냥한 도구 호출은 색인이 있을 때 평균 1.50번째, 없을 때 2.33번째였습니다. 입력 토큰은 11%, 비용은 6% 적었습니다. 하지만 질문 4개 중 2개에서만 나아서 결론을 내지 못했습니다. 이 저장소에서 색인은 대화마다 1,118자를 씁니다.
- **돈은 대화가 길어진 뒤에 나갑니다.** 만든 사람의 대화 중 호출이 20번 이상인 60개(2026-08-31–09-30, 메인 대화만)를 봤습니다. 비용의 **85%**(API 단가로 환산)가 맥락이 첫 호출의 2배를 넘은 뒤에 나갔습니다. 그래서 2배·3배에서 인계서를 쓰고 새로 시작하라고 알립니다. 끊으면 실제로 얼마나 아끼는지는 아직 재지 않았습니다.

## 개발 중: 옵시디언 노트로 만드는 개념 그래프

**개념 그래프(옵시디언 노트, 맥락 조립기)는 아직 AI가 보는 것을 바꾸지 않습니다.** 코드는 일부 있습니다. 위의 개념 색인은 이미 들어가 있지만, 그래프는 아직입니다.

풀려는 문제는 단어입니다. 사람은 일을 자기 말로 부릅니다. 그 말은 개념 제목과 잘 맞지 않습니다. 만든 사람의 사용 로그(한 사람, 저장소 하나)에서 프롬프트의 말을 개념 제목과 맞춰 봤습니다. 후보가 하나만 나왔을 때 맞는 개념이었던 비율이 <strong>0–1%</strong>였습니다. 사실상 못 맞혔습니다. 매칭 방식을 아홉 가지로 바꿔 봐도 같았고, 맞는 개념이 후보 안에 있었던 것도 54건 중 6건뿐이었습니다. 그래서 실험 기능인 개념 주입(`BATON_CONCEPT_INJECT`)은 계속 꺼 둡니다.

단어는 사람이 채워야 합니다. `driftmap`은 지난 대화 기록에서 별칭 후보를 보여 줄 수 있고, 그중 사람이 고른 것만 `CONCEPTS.md`에 `별칭=`으로 들어갑니다. 후보는 저장소 밖 캐시(`~/.cache/baton/candidates/`)에만 두고, 프롬프트 원문은 남기지 않습니다. 하지만 만든 사람의 기록으로는 쓸 만한 별칭이 하나도 나오지 않았습니다. 프롬프트 뒤에 그 개념의 파일을 연 경우가 거의 없어서 배울 재료가 모자랐습니다. 결국 단어는 사람이 직접 별칭으로 붙여야 합니다. 프롬프트마다 볼 개념·파일·결정을 고르는 맥락 조립기(`python3 lib/compiler.py explain "<프롬프트>"`)도 코드는 있지만, 아직 훅에 붙어 있지 않습니다.

계획은 개념 하나를 노트 하나로 두는 것입니다. 노트는 [옵시디언](https://obsidian.md)에서도 열리는 형식으로 씁니다.

- 노트 머리 정보(frontmatter)의 `aliases`(별칭)에 내가 그 개념을 부르는 말을 직접 적습니다. 단어를 통일하는 자리입니다. 자동으로 배우지는 않습니다.
- 노트 사이의 `[[링크]]`가 그래프의 선입니다.
- 노트 폴더는 코드 폴더 구조를 따라갑니다. 노트 위치만 봐도 코드가 어디 있는지 압니다.
- `CONCEPTS.md`는 노트에서 만들어 냅니다. 그래서 `/drift`는 그대로 돕니다.

찾을 때는 프롬프트를 별칭과 맞추고, 그 노트로 가서, 링크를 한 칸만 따라간 뒤, 파일을 읽습니다. 아직은 아무것도 동작하지 않습니다. 합격 기준을 재기 전에 정해 뒀고, 첫 별칭 매칭 시험은 그 기준을 넘지 못했습니다. 설계안: [docs/CONCEPT_GRAPH.md](CONCEPT_GRAPH.md)(소유자 승인 대기).

## 한계

- 인계서 주입은 "where were we"·"pick up where we left off"·"catch me up" 같은 영어 구에 반응합니다. 단 "continue"처럼 단어 하나에는 반응하지 않습니다(붙여 넣은 지시문·SQL에 흔해서). `/baton-setup`(`BATON_HANDOFF_TRIGGERS_EXTRA`)으로 말을 더할 수 있습니다.
- 자동 갱신은 끝난 일이 아니라 고친 파일 수를 셉니다. 작업 중간에 파일 3개를 고쳐도 걸립니다(대화에 한 번).
- 신선도는 **파일 단위**로만 계산합니다. 같은 파일의 무관한 줄이 바뀌어도 잡힙니다.
- **커밋된 이력만** 봅니다. 미커밋 변경은 `/drift`에도, 인계서의 커밋 수에도 안 잡힙니다.
- 번복(결정이 반대로 뒤집힘)은 **자동으로 찾지 못합니다.** 시도했다가 뺐습니다.
- 첫 지도는 개념마다 메타 줄을 채워야 해서 비용이 큽니다.
- 기본 문턱은 한 사람의 저장소 몇 곳으로 정했습니다. 7일 경고는 아직 잰 근거가 없는 값입니다. `/baton-setup`은 이 저장소 최상위에서 연 Claude Code 대화가 10개 이상일 때만 문턱을 바꾸자고 합니다. 하위 폴더에서 연 대화와 Codex 대화는 아직 세지 않고, 설정 절은 git 워크트리마다 따로입니다.
- 한 번만 넣기에는 사각지대가 있습니다. `/rewind` 뒤나 다른 훅이 넣은 글을 뺀 경우에도 baton은 인계서가 맥락에 있다고 보고 다시 넣지 않습니다. 그때는 AI가 파일을 직접 읽습니다. 훅이 대화 기록 경로를 받지 못하면 압축도 알아채지 못합니다. Codex에서 `/new`가 같은 대화 id를 쓰는지는 확인하지 못했습니다. 같다면 `/new` 뒤 첫 "이어서"에는 인계서가 들어가지 않습니다.
- 이름 붙은 인계서(`HANDOFF_*.md`)는 자동 갱신·제안 계산에만 쓰고 검사·주입은 하지 않습니다. `handoff-design.md`처럼 이름이 비슷한 문서도 인계서를 쓴 것으로 쳐서 제안이 빠질 수 있습니다.
- 인계서 검사기는 `postgres://user:pw@host` 같은 URL, `npm_`·`hf_` 토큰, JWT가 아닌 Bearer 값을 놓칩니다. 32자 넘는 `sk-` 브랜치 이름, CI 러너의 홈 경로, 시각 문자열을 값으로 둔 secret 대입은 잘못 잡습니다.
- 인계서를 `Edit`로 여러 번 나눠 쓰면 중간 저장마다 "필수 절 없음"이 돌아옵니다.
- 인계서 주입은 훅이 실행된 폴더의 git 최상위에서 `HANDOFF.md`를 찾습니다. Claude Code는 프로젝트 폴더에서 훅을 돌리므로 평소에는 연 저장소입니다.
- Codex에서는 새로 시작하라는 알림·인계서 자동 갱신과 제안·저장 시 자동 검사가 돌지 않습니다(대화 기록 형식이 다르고, `apply_patch`는 파일 경로를 주지 않습니다). 스킬이 검사기를 직접 돌립니다.

## 개인정보와 내 컴퓨터에서 도는 것

- 훅은 내 컴퓨터에서 도는 Python·셸 스크립트입니다. 대화 시작, `Bash` 명령과 파일 수정 뒤, 프롬프트마다, 턴이 끝날 때 돕니다. 신경 쓰인다면 설치 전에 [`hooks/`](../hooks/)를 읽어 보세요.
- 훅과 훅이 부르는 스크립트는 네트워크 요청을 하지 않습니다. git 이력과 저장소 안 파일을 읽습니다. <!-- 근거: hooks/·lib/·tools/에서 urllib·requests·curl·wget·socket·http.client·URL·git fetch/pull/push/clone 정적 검색 0건. 실행 중 추적은 아님 -->
- 인계서·알림 훅은 프롬프트마다, 인계서 검사와 알림마다 `~/.cache/baton/runs.jsonl`에 한 줄씩 남깁니다. 폴더 권한은 700, 파일은 600입니다. 20MB를 넘으면 로그를 `runs.jsonl.1`로 옮기고(전에 있던 것은 덮어씀) 새로 씁니다. 한 줄에는 저장소 경로, 규칙 판단, 실제로 넣은 것이 들어갑니다. **프롬프트 원문은 남기지 않습니다** — 해시·길이, 그리고 규칙 사전에 걸린 단어(예: "이어서", "버그")와 개념 제목만. 위치는 `BATON_LOG` 또는 `XDG_CACHE_HOME`으로 바꾸고, 끄려면 `BATON_OBSERVE=off`.
- 인계서를 한 번만 넣으려고 대화마다 작은 파일을 `~/.cache/baton/injected/`에 둡니다(인계서 해시와 대화 기록 크기, 파일 600, 7일 지나면 지움). 다른 작은 캐시·대화별 상태 파일도 같은 폴더에 둡니다.
- `/baton-setup`은 훅보다 많이 읽고(다른 프로젝트 폴더 이름, git 작성자, 미추적 파일), 스캔 출력이 대화 기록에 남을 수 있습니다. 무엇을 읽는지와 개인 자료를 대화 밖에 두는 방법은 [내 기록으로 맞추기](#내-기록으로-맞추기-선택-한-번)에 있습니다.
- 인계서·색인·알림 훅에는 끄는 변수가 있습니다: `BATON_HANDOFF_INJECT=off`, `BATON_CONCEPT_INDEX=off`, `BATON_HANDOFF_CHECK=off`, `BATON_HANDOFF_NUDGE=off`, `BATON_SPLIT_NOTICE=off`, 그리고 자동 갱신을 제안으로 되돌리는 `BATON_HANDOFF_AUTO=off`(문턱은 `BATON_SPLIT_RATIOS="2,3"`, `BATON_HANDOFF_NUDGE_FILES=3`). 환경변수로 줘도 되고 `/baton-setup`이 쓰는 설정 파일에 둬도 됩니다. 대화 시작 알림과 0건 구분 가드에는 끄는 변수가 없어서, 멈추려면 플러그인을 끕니다. 0건 구분 가드는 baton의 검사 스크립트가 0을 냈을 때, 진짜 없는 것인지 못 센 것인지 가려 말하라고 AI에게 알리는 훅입니다.

## 자주 묻는 것

**네트워크로 무엇이 나가나요?**
없습니다. 훅은 git 이력과 로컬 파일을 읽고, `~/.cache/baton/` 아래에만 씁니다. [개인정보](#개인정보와-내-컴퓨터에서-도는-것) 참고.

**토큰이 줄어드나요?**
같은 조건의 실험에서는 진행 상황 질문에서 줄었습니다. 실제 사용에서는 아직 보이지 않았습니다. [지금까지 잰 것](#지금까지-잰-것) 참고.

**`/compact`나 `/resume`과 무엇이 다른가요?**
그 둘은 한 대화를 요약과 그 뒤 메시지로 이어 갑니다. baton은 새 대화를 시작할 때 씁니다. 사람이 읽고 고칠 수 있는 짧은 인계서를 건네고, 그 인계서가 얼마나 오래됐는지 알려 줍니다. 함께 써도 됩니다.

**영어로 쓸 수 있나요?**
네. 로캘이 한국어가 아니면 메시지가 영어로 나옵니다. `BATON_LANG=en`으로 영어를 고를 수도 있습니다. 영어 요청으로도 스킬이 발동하고, 인계서 주입은 "where were we" 같은 영어 구에 반응합니다. 영어로 쓴 인계서와 개념 지도도 한국어판처럼 읽습니다. [언어](#언어) 참고.

**`DECISIONS.md`가 꼭 있어야 하나요?**
아닙니다. 파일 신선도는 git 이력만으로 돕니다. 추적되는 `DECISIONS.md`·`AGENTS.md`·`CLAUDE.md`가 하나도 없으면 결정 쪽 검사를 건너뜁니다. 그래서 "정해 놓고 아직 안 만든 것"은 못 잡고, 파일 없는 규칙 개념도 추적하지 않습니다.

**내 파일을 바꾸나요?**
훅은 알림을 내고 문제와 요청을 AI에게 돌려줄 뿐, 직접 저장소를 고치지 않습니다. `CONCEPTS.md`·`HANDOFF.md`는 요청할 때 AI가 씁니다. Claude Code에서는 하던 일이 끝나면 Stop 훅이 부탁해서 AI가 `HANDOFF.md`를 갱신하고, 커밋은 하지 않습니다(`BATON_HANDOFF_AUTO=off`로 끕니다). `/baton-setup`은 고른 값만 `~/.config/baton/config.json`에 씁니다.
