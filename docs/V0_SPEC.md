# BATON V0 — 작업 추출을 먼저 검증하고, 규칙을 채점한다

상태: 2판 (코덱스 1차 검토 반영. 구현 전 재검토 대상)
관계: `NORTH_STAR.md`의 첫 구현 단계. 여기 없는 것은 V0가 아니다.

## 한 줄

**프로젝트에 baton을 붙이는 순간, 그 프로젝트의 과거 기록으로 규칙을 시험하고 성적표를 낸다.**
아무것도 바꾸지 않는다. 기다리지도 않는다.

## 1판에서 무엇이 바뀌었나

코덱스 검토에서 열두 지적이 나왔고 전부 반영했다. 가장 큰 셋은 이렇다.

- **순서가 바뀌었다.** 규칙 채점 전에 **"무엇을 작업 문장이라 부를 것인가"부터 검증**한다.
  잘못 뽑은 문장을 아무리 잘 분류해도 성적표는 무의미하다.
- **개념 이름을 도메인으로 쓰지 않는다.** 개념("엔딩 판정")과 도메인("게임 시스템")은 다른 축이다.
  개념 이름은 도메인을 알아채는 **증거 어휘**로만 쓴다.
- **"애매함 중 사람이 답을 안 비율 = Jev 최대치"는 틀린 문장이라 뺐다.** Jev는 애매함만이
  아니라 무응답과 오답도 고칠 수 있고, 그 비율을 Jev가 다 풀어준다는 보장도 없다.

## 단계

세 단계다. 각 단계는 앞 단계의 출력이 검증돼야 시작한다.

```
STEP 0  작업 문장 추출 + 추출 정확도 검증 (사람)
STEP 1  규칙 초안 생성
STEP 2  규칙 채점 (사람 라벨)
```

### STEP 0 — 작업 문장 추출

세 출처를 **분리해서** 모은다. 한 모집단으로 합치지 않는다.

| 출처 | V0 역할 | 이유 |
|---|---|---|
| Claude Code 세션 기록 | **주 평가 대상** | baton이 실전에서 받는 것이 이 문장이다 |
| Codex 세션 기록 | 주 평가 대상 | 같음 |
| git 커밋 메시지 | **어휘 출처만.** 평가에서 제외 | 작업 지시가 아니라 결과 서술이다. 문체가 다르고, 프롬프트 하나가 커밋 다섯을 만들면 같은 사건이 다섯 번 뽑힌다 |

커밋을 어휘 출처로 쓸 때도 주의한다. 커밋은 영어 단문("fix refresh token race"), 프롬프트는
한국어 구어라 어휘가 안 겹칠 수 있다. 실제로 겹치는지 STEP 1에서 센다.

**프로젝트 귀속.** 세션 기록 폴더 이름은 경로의 한글이 대시로 바뀌어 역산이 안 된다.
파일 안의 `cwd`로 맞춘다. 비교는 문자열이 아니라 **`Path.resolve()` 후 NFC 정규화**로 한다.
`/foo/`, `/foo`, 심링크, macOS NFD 한글이 같은 곳을 가리킬 수 있다. 정규식으로 경로를 맞추지 않는다.

Codex는 `history.jsonl`(`session_id`, `ts`, `text`)과 `sessions/*.jsonl`을 **`session_id`가
세션 파일명에 포함**되는 것으로 잇는다. 시각 근접으로 잇지 않는다.

검증 기록(2026-09-21):
```
Checked: 127   Parsed: 127   Parse failed: 0   Missing cwd: 0
Schema variants: 1 (첫 줄 키 ordinal/payload/timestamp/type)
Join: history.session_id ∈ session filename — 표본 1건 확인, 전수 확인은 구현 시
```

**사람 프롬프트 판별은 구조로 한다.** `"type":"user"`에는 도구 결과가 섞여 있다.
`content`가 문자열이거나 `text` 블록만 있는 것이 사람 프롬프트다. 길이로 거르지 않는다.
"빌드 고쳐줘"는 여섯 글자지만 완전한 작업이다. 짧은 문장은 `SHORT_PROMPT` 표시만 붙인다.

**작업 경계는 후보로만 뽑고, 사람이 확정한다.**

```
SESSION_FIRST   세션의 첫 사람 프롬프트
GAP_CANDIDATE   직전 프롬프트에서 공백이 있는 프롬프트. 공백 분을 기록한다
```

30분이 경계라고 정하지 않는다. `gap_minutes`를 남기고, STEP 0 라벨링에서 사람이
"실제 새 작업인가 (예/아니오)"를 붙인다. 그러면 15분·30분·60분 기준의 정밀도를 나중에 비교할 수 있다.
**표본을 늘리려고 공백 기준을 조정하지 않는다.** 경계 정확도와 표본 크기는 별개 문제다.

1판에 적었던 "30분 기준으로 330건이 86건"은 휴리스틱이 86건을 골랐다는 뜻이지 그 86건이
진짜 작업 시작이라는 뜻이 아니다. 정밀도는 이 단계의 라벨링이 끝나야 나온다.

**STEP 0 라벨링.** `SESSION_FIRST` 20건, `GAP_CANDIDATE` 30건(공백 분 분포를 고르게)에
"새 작업인가"를 붙인다. 이 결과가 나와야 STEP 2의 표본이 정해진다.

### STEP 1 — 규칙 초안

규칙은 **두 종류**이고 출처와 적용 범위가 다르다.

| 종류 | 무엇을 판단 | 어디서 만드나 | 프로젝트 간 공유 |
|---|---|---|---|
| **전역 규칙** | 작업 종류(디버깅·구현·설계·질문), 지시 동사 | 사용자의 말 습관 | **된다** |
| **프로젝트 규칙** | 도메인, 개념, 스킬 대응 | 그 프로젝트의 어휘 | **안 된다** |

전역 규칙은 다른 프로젝트 기록으로 보정해도 된다. 운영하지 않는 프로젝트의 기록도 여기에는 쓴다.
도메인 규칙은 그 프로젝트 기록으로만 보정한다. 큰 프로젝트에서 맞춘 도메인 규칙을 작은 프로젝트에
넘기면 표본 부족을 분포 차이로 덮는 것이다.

**도메인은 `init`이 확정하지 않는다.**

```yaml
domains:
  status: unconfigured        # 사람이 정하기 전까지

domain_evidence:               # 도메인을 알아채는 어휘. 도메인 자체가 아니다
  from_concepts: [엔딩 판정, 잔상, 레이저]
  from_agents_md: [그래프 적립 장치]
  from_dirs: [src, specs, sim-tests]
  from_commits: [...]          # 어휘만. 평가 모집단이 아님

candidate_domains:             # 자동 제안. 확정 분류 체계인 척하지 않는다
  - name: 게임 시스템
    evidence: [엔딩 판정, 잔상]
```

`CONCEPTS.md`의 개념이 그 프로젝트의 도메인과 같은 층위인지는 **확인된 바 없다.** 프로젝트마다
개념의 굵기가 다르다("Authentication" vs "Refresh Token Rotation"). 1판의 "실제 세 프로젝트가
그렇다"는 근거 없는 문장이었다.

규칙 결과는 확률이 아니라 **상태**다.

```
MATCHED     증거가 하나로 모임
AMBIGUOUS   증거가 둘 이상에 걸림
NO_MATCH    증거 없음
```

증거 우선순위: 사용자 명시 태그 > 정확한 구("refresh token") > 두 단어 조합 > 단독 키워드.
단독 키워드는 도메인을 정하지 못한다. "세션"은 인증일 수도 핸드오프일 수도 있다.

### STEP 2 — 규칙 채점

**표본은 층별 최소치로 잡는다.** 총량 기준(64/80)은 쓰지 않는다. 총량을 채웠어도 `NO_MATCH`를
하나도 안 봤으면 분석 가치가 없다.

```
MATCHED    최소 20
AMBIGUOUS  최소 20
NO_MATCH   최소 10
```

**라벨링 화면에서 규칙의 예측을 숨긴다.** 예측을 보면 사람의 답이 거기에 끌린다.
저장한 뒤에만 "규칙은 이렇게 봤다"를 보여 준다.

**정답은 하나가 아닐 수 있다.**

```
label_type:  SINGLE | MULTI | NONE | UNCLEAR
domains:     ["auth", "infra"]      # MULTI면 둘 이상
```

"인증 API 고치고 배포 설정까지"는 두 도메인이 정답이고, 규칙이 `AMBIGUOUS`라 한 것이 **맞은 것**이다.
이 구분 없이는 애매함 성능 자체를 잴 수 없다.

## 성적표

`.baton/calibration.md`. **층별 지표만 낸다.** 전체 정확도는 층별 비율로 가중해야만 의미가 있고,
V0에서는 내지 않는다.

```
STEP 0  작업 경계 정밀도
  SESSION_FIRST  새 작업 비율  95%  (20건)
  GAP >= 15분    새 작업 비율  60%  (10건)
  GAP >= 30분    새 작업 비율  80%  (10건)
  GAP >= 60분    새 작업 비율  90%  (10건)

STEP 2  규칙 (프로젝트: 문서, 표본 MATCHED 20 / AMBIGUOUS 20 / NO_MATCH 10)
  MATCHED   중 맞힘                         78%
  AMBIGUOUS 중 사람은 단일 도메인            40%   ← semantic disambiguation opportunity
  AMBIGUOUS 중 사람도 MULTI                  35%   ← 규칙이 맞은 것
  NO_MATCH  중 사람은 답이 있음              70%   ← 어휘 부족

전역 규칙 (작업 종류, 4개 프로젝트 합산)
  MATCHED 중 맞힘                            84%
```

**"semantic disambiguation opportunity"는 Jev의 최대치가 아니다.** Jev가 손댈 수 있는 자리는
셋이다(애매함 해소, 무응답 해소, 오답 교정). 실제 가치는 나중에 **같은 라벨 집합에서
Rules only 대 Rules + Jev를 직접 비교**해야 나온다. 이 숫자는 그 비교를 할 가치가 있는지만 말한다.

**이 성적표의 정확한 뜻.** "규칙이 과거에도 옳았는가"가 아니라 **"지금 프로젝트 어휘로 만든
규칙이 과거 표현을 얼마나 덮는가"**다. `CONCEPTS.md`가 최근에 커졌다면 미래 어휘로 과거를
분류하는 시간 누출이 있다. V0에서는 허용하되 성적표 머리에 이 문장을 그대로 적는다.

**표본이 적으면 숫자 대신 상태를 낸다.**

```
도메인 채점 (프로젝트: 앱)
  표본 15건 · 상태 LOW_SAMPLE · 수치를 내지 않는다
```

"프로젝트당 50건" 같은 문턱은 두지 않는다. 기준선을 만드는 단계라 15건·30건·80건에서
불확실성이 얼마나 다른지를 보고 나중에 정한다.

## `init`의 실행 계약

- 세 단계를 순서대로 밟는다. 실패하면 **어느 단계에서 왜**를 매니페스트에 남기고 멈춘다.
  ```json
  {"run_status": "FAILED", "failed_stage": "codex_history_extract", "reason": "..."}
  ```
- 결과 파일은 임시 파일에 쓰고 성공 후에만 제자리로 옮긴다. 반쯤 쓰인 `calibration.md`가
  완료된 것처럼 보이면 안 된다.
- 모든 수치는 **센 것 · 못 센 것 · 이유**를 함께 낸다. 0은 "없음"이 아니라 "못 셌음"일 수 있다.

## V0에 없는 것

- 훅. 프롬프트를 가로채지 않는다.
- 컨텍스트 제거, 스킬 필터, 자동 핸드오프, 에이전트 라우팅.
- Jev.
- 그래프·온톨로지 수정. 읽기만 한다.
- 기존 driftmap·baton 스킬 변경.
- 전체 정확도 한 숫자. 층별만.

## 파일

```
.baton/
  rules.yaml          규칙. 전역/프로젝트 구분
  tasks.jsonl         추출한 문장. source · boundary_type · gap_minutes · SHORT_PROMPT
  labels.jsonl        사람 답. STEP 0 경계 라벨 + STEP 2 도메인 라벨(label_type 포함)
  calibration.md      성적표
  run.json            매니페스트
```

구현은 파이썬 파일 하나(`observer/baton_init.py`)와 규칙 파일 형식뿐이다.

## 구현 전 재검토가 필요한 자리

1. STEP 0 라벨 표본 20 + 30이 경계 정밀도를 말하기에 충분한가. 근거 없이 잡았다.
2. `candidate_domains` 자동 제안을 아예 빼고 `unconfigured`로만 시작하는 게 더 정직한가.
3. 커밋을 어휘 출처로 남기는 것이 실익이 있는가. 한국어 프롬프트와 영어 커밋의 어휘 겹침을 재본 뒤 결정.
4. `session_id ∈ filename` 연결을 표본 1건으로만 확인했다. 구현 시 전수 확인하고 기록을 남긴다.
