# 개념 그래프 — 옵시디언 노트로 (설계안 2판, 2026-11-21 · 소유자 승인 전)

> **소유자의 말(2026-11-21, 원문).** "우리의 목표는 토큰을 효율적으로 사용하기 위해서는 읽을 내용을 줄여야 한다는 철학에서 접근해서 핸드오프를 통해 세션 시작 시 읽을 양을 효율적이게 하고, 온톨로지를 통해 옵시디언과 단어 통일화를 시켜서 빠르게 정보를 찾게 하는 거야. 그럼 컨텍스트도 안 늘고, 새 세션 때 완벽해질 테니까, 그리고 그럼 나아가서 착각하는 문제도 발생 안 해." · "개념 그래프를 만들고 싶은 거야. 거기다가 폴더 위치에 대한 정보도 들어가는 옵시디언 특성도 활용해서." (오타·띄어쓰기만 고침, 첫머리 "그리고"는 뺐다)
> **소유자 선택(같은 날, 세션이 낸 선택지에서).** 노트는 **각 저장소 안 폴더**에 둔다. 폴더 구조는 **코드 폴더 구조를 따라간다**.
> 이 문서는 `docs/research/ONTOLOGY_DESIGN.md`(10-04 소유자 승인, P1~P4)를 이어받는다. P3(별칭 후보 루프)·P4(조립기)의 재료를 옵시디언 노트 형식으로 바꾸는 것이 이 문서의 몫이다. 아래 "착각이 없다"는 0을 약속하지 않는다 — 줄어드는 수치로 잰다(6절).

## 1. 왜 바꾸나 — 단어가 안 맞아서 못 찾는다

- 개념 후보 매칭(개념 제목 단어가 프롬프트에 부분 문자열로 들어 있나)은 실사용 로그에서 쓸 수 없었다. 후보가 하나일 때 맞힌 비율이 현행 0/112, 매칭 개선안 9가지 모두 0~1%(최선 1/159). 맞는 개념이 후보 안에 있던 것도 54건 중 6건(11%)뿐이다(`docs/research/LOOP_PLAN.md` 11-21 절). **한계: 한 사람·한 저장소 로그, 정답은 대리 신호**(프롬프트 뒤 도구 호출 10번 안에 그 개념 절이 가리키는 파일을 열었나).
- 원인으로 보는 것: 규칙이 아니라 **단어**다. 사람이 일을 부르는 말과 개념 제목이 다르다. 그래서 개념마다 사람이 실제로 쓰는 말을 별칭으로 붙인다 — 북극성 단계 2("짧은 별칭은 사람이 붙인다")와 같은 방향이고, 아직 입증은 안 됐다.
- 위치가 단서가 된다는 신호도 있다. 09-21 V0 측정에서 도메인 어휘 적중 3.3%의 대부분은 **폴더명**이었다(개념 제목은 1건, 다른 매처 — `docs/NORTH_STAR.md` 2절). 10-04 오프라인 평가에서는 공유 커밋 그래프가 "같은 폴더 최근순" 기준선을 못 이겼다(표본 미달 n=16, 참고값 — `ONTOLOGY_DESIGN.md` 3-1·3-2). 폴더 위치를 쓰자는 소유자 선택과 같은 쪽이다.

## 2. 옵시디언 기능이 그래프의 재료가 된다

| 옵시디언 | 개념 그래프에서 | 목표와의 연결 |
|---|---|---|
| 노트 하나 | 개념 하나 | — |
| 노트 머리의 `aliases` | 그 개념을 부르는 여러 말 | **단어 통일** — 프롬프트의 말을 별칭과 맞춘다 |
| `[[링크]]` | 개념 사이 간선(관계 이름을 붙인다) | 이웃은 한 칸만 따라간다 |
| 폴더 경로 | 개념이 사는 코드 위치(사람이 보는 정리) | 노트 위치로 열 파일 근처를 바로 안다 |
| 그래프 보기·이름 바꾸면 링크 갱신 | 사람이 지도를 보고 고치는 화면 | 고치기 쉬워야 지도가 낡지 않는다 |

baton은 옵시디언 앱 없이 돈다. 노트는 평범한 마크다운이고, 옵시디언은 사람이 보는 화면이다. 옵시디언 밖에서 이름을 바꾸면 `[[링크]]`가 조용히 깨지므로 검사가 잡는다(5절).

## 3. 노트 형식

```markdown
---
no: 7
summary: 상태 질문이면 인계서를 세션에 한 번 넣는다
aliases: [인계서 주입, 이어서, handoff inject]
status: 일치
severity: —
checked: 2026-11-21
checked_commit: a5f18ca
files: [hooks/handoff-inject.py, lib/rules.py]
docs: [README.md, README.ko.md]
---
# 인계서 주입

- **정해진 것**: …(DECISIONS.md 항목)
- **실제 동작**: …(`hooks/handoff-inject.py:150` 같은 근거)
- **설명된 곳**: …
- **어긋남**: …

## 이웃
- 정본: [[인계서 상한]]
- 전제: [[설정 파일과 우선순위]]
```

- 머리 항목은 지금 `CONCEPTS.md` 메타 줄(상태·확인·파일·문서)과 요약표의 번호(`no`)·심각도·한 줄(`summary`)을 옮긴 것이다. 요약표의 행 순서는 지금 스킬 규칙(어긋난 것이 맨 위, 심각도순, 같으면 번호순)을 생성기가 그대로 따른다. `status`는 지금 어휘 그대로(`해소됨(2026-11-21)` 같은 꼴 포함)를 문자열로 둔다. 본문 네 칸도 그대로다.
- **위치의 정본은 `files:` 하나다.** 노트가 놓일 폴더는 `files:`에서 **규칙으로 계산**한다: 모든 파일의 가장 긴 공통 폴더, 그 첫 칸이 점(`.`)으로 시작하면 `concepts/` 바로 아래(옵시디언은 점 폴더를 안 보인다), 공통 폴더가 없거나 `files:`가 비었으면(폐기된 개념 등) `concepts/` 바로 아래. 예) `hooks/handoff-inject.py` 하나 → `concepts/hooks/`, `hooks/…`+`lib/…` → `concepts/`. 검사가 "노트 폴더 = 계산한 폴더"를 본다 — 폴더와 `files:`가 따로 놀지 않게. 코드 폴더를 옮기거나 `files:`를 바꾸면 노트 폴더도 바뀔 수 있다 — 검사가 옮기라고 알린다(노트 이동이 잦아질 수 있는 비용). `[[링크]]`는 경로가 아니라 노트 제목으로만 건다.
- 이웃은 `[[노트 제목]]` + 관계 이름(정본·전제 등, 지금 `이웃=` 어휘). **양방향은 한쪽만 적어도 된다** — 생성기가 옵시디언 백링크처럼 반대쪽을 계산해 색인에 함께 낸다. 지금 스킬의 "한쪽만 적힌 간선은 끊어진 간선" 규칙은 "링크 대상 노트가 없음"으로 바뀐다.
- `concepts/.obsidian/`(사람의 화면 설정)은 `.gitignore`로 뺀다.

## 4. 정본은 하나 — 노트가 정본, `CONCEPTS.md`는 만들어지는 색인

- 옮길 때 한 번: 지금 `CONCEPTS.md` → 노트들(변환기, 결정론).
- 그 뒤로 노트가 정본이다. `CONCEPTS.md`는 노트에서 **생성**하는 색인(머리말·요약표·개념별 메타 줄·"일치 확인된 것"·"폐기된 개념"·"확인하지 못한 것"·"유지 규칙")으로 두고 맨 위에 "생성됨 — 손으로 고치지 않는다"를 적는다. 개념에 속하지 않는 절은 손으로 쓰는 `concepts/_색인.md`가 정본이다.
- **합격 조건(변환·생성기)**: 이 저장소 지금 지도를 노트로 바꿨다가 다시 생성하면 메타 줄·요약표가 바이트 단위로 같다(테스트). 그래야 `CONCEPTS.md`를 읽는 `fresh.sh`·`check.sh`·`/drift`가 그대로 돈다. 별칭(`별칭=`) 해석은 그래프 이식 PR(`lib/candidates.py`)이 들어온 뒤라야 쓸 수 있다.
- 생성본이 노트와 같은지는 테스트와 CI가 본다 — 노트를 고칠 때마다 생성기를 다시 돌려야 하는 비용이 생긴다(7절 위험).
- 하지 않는 것: 노트와 `CONCEPTS.md`를 둘 다 손으로 고치는 양방향 동기화(정본이 둘이 된다).
- **이 스킬의 지난 근거와 부딪히는 곳(밝힌다).** `skills/driftmap/SKILL.md`는 "새 파일을 만들지 않는다 — `CONCEPTS.md` 하나"를 조건으로 둔다. 손으로 유지하던 관계도가 1주간 한 번도 안 열렸기 때문이다("열 계기가 없어서"). 이 설계는 노트를 여러 개 만들지만, **에이전트가 읽는 것은 여전히 `AGENTS.md`에서 링크된 `CONCEPTS.md` 하나**이고 노트는 사람의 편집 화면이다. 열 계기는 생성된 색인이 지킨다. 스킬의 "고치기는 승인 뒤에만"(모드 ⑦)도 그대로 — 생성기는 노트를 바꾸지 않고 색인만 만든다.

## 5. 찾는 법 — 별칭 → 노트 → 이웃 한 칸 → 파일

1. 프롬프트의 말을 노트의 `aliases`·제목과 **낱말 단위로** 맞춘다. 한국어는 낱말 뒤에 붙는 **고정 조사 목록**(은·는·이·가·을·를·의·에·에서·으로·로·와·과·도·만 등, 목록은 코드에 고정)만 떼고 비교한다. 별칭은 2글자 이상, 2글자 한글 별칭은 낱말 전체가 같을 때만 맞는다 — 11-21 분석에서 2글자 한글 제목 단어가 부분 문자열로 거의 다 걸린 것이 실패 원인이었다. 사람이 아닌 프롬프트(다른 세션 메시지, `MACHINE` — PR #16 뒤)는 세지 않는다.
2. 프롬프트에 파일 경로가 있으면 그 파일을 `files:`에 가진 노트를 후보에 더한다(폴더가 아니라 `files:`로 찾는다 — 붐비는 폴더의 노트가 몽땅 딸려 오지 않게).
3. 맞은 노트 + `[[링크]]` 한 칸 이웃만 모은다. 공유 파일 동시출현 간선은 만들지 않는다(09-21: 개념 9개에 간선 36개로 폭발).
4. 조립기(P4)가 예산 안에서 노트 본문 대신 **메타·근거 줄**만 싣는다. 실제 동작은 에이전트가 근거 파일을 연다.

별칭은 두 곳에서 온다: 사람이 붙인 것, 그리고 P3 루프(`lib/candidates.py`) — 프롬프트 뒤에 실제로 그 개념의 파일을 연 기록에서 별칭 후보를 뽑고, 결정론 검증 뒤 **사람이 승격**한다(스펙 21절).

### 바뀌는 도구

| 도구 | 바뀌는 것 |
|---|---|
| `lib/concepts.py` | 노트 읽기(머리 항목·`[[링크]]`), 색인 생성, 노트 폴더 계산 |
| `lib/check.sh` | `[[링크]]` 대상 있음, 제목·별칭이 노트끼리 겹치지 않음, 노트 폴더 = 계산한 폴더, 생성본 = 노트 |
| `lib/fresh.sh` | 그대로(생성된 메타 줄을 읽는다) |
| `skills/driftmap/SKILL.md` | 고치는 곳이 `CONCEPTS.md`가 아니라 노트, 양방향 규칙의 바뀐 뜻(3절), 별칭 승격은 노트 머리에 |
| CI | 생성본이 노트와 같은지 검사 한 단계 |

## 6. 합격선 — 재기 전에 고정하고, 결과를 본 뒤 바꾸지 않는다 (소유자 확인 필요)

평가 재료: ① 이력에서 뽑은 사례 모음 20건(`observer/research/cases.json`, 로컬 전용) ② 실사용 로그의 대리 정답(1절과 같은 정의).

| 비교 | 지금 값 | 제안 합격선 |
|---|---|---|
| 후보가 하나일 때 맞힌 비율(대리 정답, **별칭 적중만**) | 제목 매칭 0/112 | **30% 이상** |
| 맞는 개념이 후보 안에 있는 비율(recall) | 6/54(11%) | **50% 이상** |
| 후보 10개 이상인 프롬프트 | 기계 프롬프트 제외 뒤 17건(그 제외는 PR #16 몫) | 별칭 매칭에서 5건 이하 |
| 사례 모음 정답률 | — | 기준선(규칙만·메인 모델 자가 선택)보다 1건 넘게 낮지 않음(n=20에서 1건 = 5%p), 실은 맥락은 줄어듦 |

- **경로 적중(5절 2단계)은 따로 보고한다.** 노트 폴더가 코드를 따르므로, 프롬프트에 경로가 있으면 대리 정답과 거의 저절로 맞는다 — 섞으면 별칭의 효과를 못 본다.
- 30%·50%·5건은 근거 없는 출발값이다 — 소유자가 정한다. 못 넘으면 그 단계에서 멈추고 그 게이트는 끈다(정본 46절).

## 7. 위험 (승인 전에 알아야 할 것)

1. **개인정보.** `concepts/`는 공개 저장소에 커밋된다. P3 루프는 사용자 프롬프트의 말에서 별칭 후보를 뽑는다 — 승격된 별칭은 공개 이력에 남는다. 그래서 승격은 사람만 하고, 승격 전에 인계서 검사기의 홈 경로·개인 자료 단어 검사(`lib/handoff_check.py`)를 돌린다(그래프 이식 PR의 `leaks()`). 노트 전체에도 같은 검사를 CI에서 돌린다.
2. **한국어 조사 처리.** 조사를 넉넉히 떼면 다시 부분 문자열 오탐이 생긴다. 조사 목록과 최소 길이를 코드에 고정하고, 실패 사례(2글자 한글)를 테스트로 박는다. 그래도 합격선을 못 넘으면 형태소 분석기 없이 가는 이 방식의 한계로 기록한다.
3. **링크 무결성.** 옵시디언 밖(에이전트·`git mv`)에서 노트 이름을 바꾸면 `[[링크]]`가 깨진다. 별칭이 노트끼리 겹치면 `[[x]]`가 모호해진다 — 둘 다 `check.sh`가 잡는다(5절 표).
4. **CI·유지 비용.** 노트를 고칠 때마다 생성기를 다시 돌려야 한다. 생성 순서는 결정론(요약표는 스킬 규칙 순, 개념 절은 번호 순)으로 고정한다.
5. **여러 폴더에 걸친 개념.** 공통 폴더 규칙 때문에 루트(`concepts/`)로 몰릴 수 있다 — baton 자기 지도에서 몇 개가 루트로 가는지 변환 뒤 센다.
6. **근거가 한 사람·한 저장소.** 다른 성격의 저장소(게임·앱·문서)에서 폴더 규칙이 맞는지는 아직 모른다.

## 8. 순서

1. **합치기** — `compiler-shadow` 브랜치에만 있던 그래프 작업(P1 평가·P3 후보 루프·P4 조립기)을 main으로(PR, 훅 연결은 #16·신선도 PR 뒤).
2. **노트 형식·변환기·생성기·검사** — 3~5절. baton 자기 지도로 왕복 동일부터.
3. **별칭으로 찾기 + 오프라인 평가** — 6절 합격선 판정(비용 0).
4. 합격하면 조립기에 연결(그림자 모드 → 켜기). 불합격이면 끈 채로 두고 수치를 기록한다.

## 9. 소유자가 정할 것

1. 6절 합격선(30%·50%·5건이 적당한가).
2. 노트 폴더 계산 규칙(3절: 가장 긴 공통 폴더, 점 폴더·공통 없음은 루트). **변환을 한 번 돌려 루트로 몰리는 개념 수를 본 뒤에** 정한다 — 많이 몰리면 "폴더 = 코드 위치"가 일부 노트에서만 참이 된다.
3. `concepts/` 폴더 이름(옵시디언 볼트로 열 폴더).
