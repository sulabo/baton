# baton 1.0.0-beta.4 — 영어 화면, 인계서 자동 갱신

**Stop your AI agent from re-reading your project every new session.**
baton now speaks English as well as Korean: every hook message, script output, skill and command has both, and `BATON_LANG` picks one. When a piece of work ends, the agent updates `HANDOFF.md` for you (Claude Code), and saving a handoff warns you about lines that were dropped.
English overview: [README.md](https://github.com/sulabo/baton#readme) · homepage: https://sulabo.github.io/baton/

AI가 새 대화마다 프로젝트를 처음부터 다시 읽지 않게 하는 Claude Code·Codex 플러그인입니다.
이번 판은 영어 화면을 더하고, 하던 일이 끝나면 에이전트가 인계서를 알아서 고치게 했습니다.

## 30초 설치

Claude Code 안에서:

```
/plugin marketplace add sulabo/baton
/plugin install baton@baton
```

이미 설치했다면 터미널에서 `claude plugin marketplace update baton` → `claude plugin update baton@baton`을 돌리고 창을 새로 엽니다. 열려 있던 창은 옛 훅을 계속 씁니다. Codex는 `codex plugin marketplace upgrade baton`.
필요한 것은 `git`과 `python3`뿐입니다. Codex(0.155 이상)는 `codex plugin marketplace add sulabo/baton` → `codex plugin add baton@baton`.

**업데이트하면 메시지 언어가 바뀔 수 있습니다.** 언어는 `BATON_LANG` > 로캘(`LC_ALL`·`LC_MESSAGES`·`LANG`) 순서로 정합니다. 한국어로 쓰던 분인데 `LANG`이 `en_US`라면 영어로 나옵니다. `/baton-setup`에서 `BATON_LANG=ko`를 고르거나, 환경변수 `BATON_LANG=ko`를 주세요. `/baton-doctor`가 지금 언어와 그 값이 어디서 왔는지 보여 줍니다.

## 이번 판에서 바뀐 것

- **영어 화면.** 훅 메시지, 스크립트 출력, 스킬, 명령에 영어를 더했습니다. 언어는 `BATON_LANG`(`ko`·`en`·`auto`)으로 정하고, 정하지 않으면 로캘을 따릅니다. 로캘 변수가 하나도 없는 macOS(앱에서 연 경우 등)에서는 시스템 언어 목록을 봅니다. 파일 형식은 언어 설정과 상관없이 두 언어 모두 읽습니다(`HANDOFF.md`의 영어 절 제목, `CONCEPTS.md`의 `- **Meta**:` 줄, `DECISIONS.md`의 `Related:`).
- **인계서 자동 갱신**(Claude Code, 기본 켬). 마지막 인계서 뒤로 파일을 3개 이상 고쳤으면, 턴이 끝날 때 한 대화에 한 번 에이전트에게 `HANDOFF.md`를 고치라고 합니다. 에이전트는 지금 파일에서 시작해 고치고, 커밋하지 않고, "인계서를 고쳐 뒀어요"라고 한 줄로 알립니다. 다른 형식의 `HANDOFF.md`가 있는 저장소에서는 고치지 않고 제안만 합니다. 끄기: `BATON_HANDOFF_AUTO=off`(제안만), `BATON_HANDOFF_NUDGE=off`(둘 다).
- **저장할 때 빠진 줄 경고.** 저장한 인계서를 마지막 커밋판과 비교해, 실패한 접근법·승격 후보·기각 목록에서 빠진 줄과 결정·제약 표지가 붙은 줄이 빠진 것을 알려 줍니다. 막지 않고 경고만 합니다. 비밀값 차단은 이 비교보다 먼저 나가고, 비교는 2초 안에 끝냅니다.
- **필독 표시.** 인계서의 파일 목록에서 `(필독)`·`(must read)`를 붙인 항목(최대 3개)을 인계서를 넣을 때 맨 앞쪽 한 줄로 다시 보여 줍니다.
- **알림을 쉬운 말로.** 화면에 뜨는 알림(맥락 2·3배, 인계서 제안, 0건, 대화 시작)을 해요체와 짧은 영어로 다시 썼습니다.
- **스킬·명령이 스크립트를 바로 찾습니다.** 경로를 `${CLAUDE_PLUGIN_ROOT}` 꼴로 적고, 읽기만 하는 스크립트는 미리 허용합니다. `claude -p`에서 `/drift`가 권한 확인 없이 도는 것을 확인했습니다.
- 고친 것: `/promote`가 "- 없음"을 항목으로 세던 문제, 0건 알림이 개념 이름이나 하위 집계의 0에 울리던 문제, `docs=none`을 문서 경로로 읽던 문제, `check.sh`가 가끔 잘못 읽던 문제(SIGPIPE).

## 아직 확인하지 못한 것

- **실사용에서 토큰이 줄었는지는 아직 모릅니다.** 같은 인계서를 한 대화에 한 번만 넣게 고친 beta.3 이후의 실사용 기록을 모으는 중입니다.
- **자동 갱신은 실제 대화에서 써 본 기록이 없습니다.** 테스트로만 확인했습니다. 도움이 되는지, 거슬리는지는 써 봐야 압니다.
- **빠진 줄 경고의 오탐은 저장소 하나에서 약 20%였습니다.** 다른 저장소에서는 모릅니다.
- **새로 시작하기와 `/compact` 중 어느 쪽이 나은지는 아직 재는 중입니다.** 홈페이지와 README는 이 비교를 주장하지 않습니다.

## 알려진 한계

- 베타입니다. 수치는 만든 사람 한 명의 기록에서 나왔습니다.
- 신선도 줄의 커밋 수와 `/drift`는 커밋된 이력만 봅니다.
- 자동 갱신, 새로 시작하라는 알림, 저장할 때 자동 검사는 Claude Code에서만 돕니다.
- 인계서를 넣는 말은 프롬프트 어디에 있어도 걸립니다. 붙여 넣은 글 속의 "이어서"에도 인계서가 들어갑니다.
- 플러그인이 띄어쓰기가 있는 경로에 설치되면 스킬이 스크립트를 실행하지 못할 수 있습니다(기본 설치 경로에는 없습니다).
- 인계서 검사기는 일부 비밀값 형식(`postgres://user:pw@host`, `npm_`·`hf_` 토큰, JWT가 아닌 Bearer 값)을 놓칩니다.
- `/rewind` 뒤에는 인계서가 맥락에 있다고 보고 다시 넣지 않습니다.
