문제

새 대화는 읽는 일부터 시작해요.

만든 사람의 기록을 보면, "어디까지 했지?"로 시작한 대화 42개 중 41개에서 AI가 첫 5번 호출 안에 HANDOFF.md를 다시 읽었어요. 읽은 내용은 대화가 끝날 때까지 맥락에 남아, AI를 부를 때마다 다시 보내져요. 오래된 메모는 지금 코드와 어긋나 있을 수도 있어요.

작동 방식

한 장으로 넘기고, 바뀐 곳만 다시 읽어요.

  1. 1 · 대화를 마칠 때

    인계서를 써요. 저장하는 순간 검사해요.

    "인계서 써 줘"라고 말하세요. 정해진 때에 도는 작은 스크립트(훅)가 길이, 꼭 있어야 하는 8개 항목, 비밀값, 홈 폴더 경로, 직접 정해 둔 비공개 단어를 검사해요. 문제가 있으면 AI에게 돌려줘요.

  2. 2 · 다음 대화

    "어디까지 했지?"라고 물어요. 인계서가 작성 시점과 함께 한 번 들어가요.

    훅이 인계서를 맥락에 넣으면서, 언제 썼는지와 그 뒤 커밋이 몇 개인지 알려 주는 한 줄을 붙여요. 한 대화에 한 번만 넣고, 보조 AI(서브에이전트)가 보낸 메시지에는 넣지 않아요.

  3. 3 · 커밋한 뒤

    파일이 바뀐 개념만 다시 봐요.

    CONCEPTS.md는 개념마다 관련 파일과 마지막으로 확인한 커밋을 묶어 둬요. baton은 신선한지 짐작하지 않고, 커밋 수를 세요.

개념 지도

셀 수 없으면, 셀 수 없다고 말해요.

한 번도 확인하지 않은 개념은 기준이 없어요. 그래서 신선하다고 세지 않고 따로 표시해요. 판정은 모두 커밋 수이거나, 이름이 붙은 이유예요.

  • 신선확인한 뒤로 커밋이 없어요. 다시 읽을 게 없어요.
  • 커밋 N건확인한 커밋 뒤에 이 개념의 파일이 바뀌었어요.
  • 기준 없음확인한 커밋이 아직 기록되지 않았어요.
  • 문서 커밋 N건코드는 그대로인데, 그 코드를 설명하는 문서가 바뀌었어요.

지금까지 잰 것

잰 것과, 아직 못 잰 것.

숫자는 모두 만든 사람 한 명이 자기 저장소에서 쓴 기록이에요. 숫자마다 기간과 범위가 달라요. 명령과 출처는 변경 기록에 있어요.

설치 전 08-31~10-04, 설치 후 10-19~11-20. 설치 후 대화가 11개라, 효과의 크기보다 방향을 보여 줘요.

40–54%

진행 상황을 물을 때 인계서를 넣어서 줄어든 입력 토큰이에요. 같은 저장소 상태에서 되풀이한 실험(스냅숏) 결과예요.

저장소 3곳, 조건마다 3~5번. 관련 없는 작업에 인계서를 넣으면 약 11% 더 썼어요.

아직

실제 사용에서는 아직 토큰이 줄지 않았어요. 같은 인계서가 대화 39개에서 269번 들어갔어요. 대화마다 한 번만 넣도록 고쳤고, 그 효과는 아직 재지 못했어요.

10-04~11-19. 같은 기간에 다른 플러그인이 처음부터 차지하는 맥락도 커졌어요.

85%

맥락이 첫 호출의 2배를 넘은 뒤에 나간 비용이에요. 그래서 baton은 2배와 3배일 때 인계서를 쓰자고 알려요.

AI 호출이 20번 이상인 대화 60개, API 가격 기준.

    한 대화에 한 번만 넣고, 보조 AI나 다른 대화가 보낸 메시지에는 넣지 않아요.

설치하기 전에.

baton이 인터넷으로 무언가를 보내나요?

아니요. 훅은 git 기록과 내 컴퓨터의 파일만 읽고, ~/.cache/baton/ 아래에만 써요.

토큰이 줄어드나요?

스냅숏 실험에서는 진행 상황을 물을 때 줄었어요. 실제 사용에서는 아직 줄어든 걸 보여 주지 못했어요. 숫자와 범위는 위의 "지금까지 잰 것"에 있어요.

/compact나 /resume과 뭐가 달라요?

그 둘은 대화 하나를 요약과 그 뒤 메시지로 계속 이어 가요. baton은 새 대화를 시작할 때 써요. 직접 읽고 고칠 수 있는 짧은 인계서를 AI에게 건네고, 그 인계서가 얼마나 오래됐는지도 알려 줘요. 둘을 같이 써도 돼요.

어떤 말을 하면 인계서가 들어가나요?

"이어서", "어디까지", "인계", "handoff" 같은 말이 프롬프트에 있으면 들어가요. 그런 말이 없으면 넣지 않아요. 말은 /baton-setup으로 더 넣을 수 있어요.

DECISIONS.md가 꼭 있어야 하나요?

아니요. 파일 신선도는 git 기록만으로 돼요. 결정 기록이 없으면 "정했는데 아직 안 만든 것"은 잡지 못하고, 파일이 없는 개념은 추적하지 않아요.

내 파일을 바꾸나요?

훅은 알림을 보여 주고 문제를 AI에게 돌려줄 뿐이에요. CONCEPTS.md와 HANDOFF.md는 요청할 때 AI가 써요.

한 번 적어 두면, 다음 대화는 거기서 시작해요.
