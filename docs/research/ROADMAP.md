Claude Code든 Codex든 이 문서만 보고 이어서 할 수 있게 쓴다. 근거 수치와 실행 명령은 `LOOP_PLAN.md`에 있다.

## 왜 이 순서인가 — 토큰이 나가는 공식

세션 입력 토큰 = **각 API 호출의 입력·캐시 생성·캐시 읽기 토큰 합을 호출별로 더한 값**.
`평균 컨텍스트 × 호출 수`는 이를 설명하는 근사다. 실제 요금은 캐시와 모델 단가에 따라 달라 별도로 잰다.
게임 저장소 실측: 첫 턴 약 44K로 시작해 6턴 동안 약 35만 토큰.

| 지렛대 | 오늘까지의 실측 | 담당 |
|---|---|---|
| 턴 수 | 인계서 on-demand 주입으로 5~6턴 → 3턴, 토큰 -43~54% (저장소 3곳) | 핸드오프 |
| 읽는 양 | 개념 지도 있음: 오답 1건 방지, -15% (사례 1개, n=3) | 개념 그래프 · Jev |
| 고정분 | 첫 턴 44K = Claude Code 자체 ~17K(추론) · 전역 지침 ~12K(추정) · 플러그인+스킬+MCP ~11K · 프로젝트 ~4K. OMC 단독 ~3K | ECC · (담당 없음) |

턴 하나를 줄이는 것이 고정분 수천 토큰보다 크다(OMC를 빼면 첫 턴 -7%, 세션 전체 -2%). 그래서 순서는
**실사용 측정 → 턴 줄이기 확장 → 고정분 → 개념 그래프 수지 → 정답 사례 → Jev → 연결·대칭**이다.

## 공통 가드 (모든 단계)

- 한 세션 최대 **5라운드**. 라운드마다 예산 상한(`--max-usd`)을 먼저 정한다. 세션 합계 **USD 40** 넘으면 멈춘다.
- **같은 실패 2회 연속이면 멈추고 보고.** 사용량 한도에 걸리면 멈춘다(러너가 `is_error`로 제외).
- **원본 저장소는 읽기만.** 실험은 `.data/snapshots/`의 스냅샷에서만. 실험 뒤 원본 경로 접근·Write/Edit 0건을 확인해 기록한다.
- **채점기 출력은 확정이 아니다.** 판정은 발화가 아니라 행동(도구 호출·diff)으로 하고, 결과를 적기 전에 전수 원문 대조한다.
  오늘 정규식 채점기가 두 번 틀렸다(`LOOP_PLAN.md` 루프 2·4).
- 결과는 작업 파일로 남긴다. 커밋·푸시는 소유자가 요청할 때만 하며 기본 브랜치에 직접 커밋하지 않는다. **플러그인 설치·전역 지침 수정은 소유자만.**
- 러너는 `claude -p`를 부른다. Codex에서 진행하면 Codex 한도(명령·판독)와 Claude 한도(러너가 띄운 세션)가 **둘 다** 든다.
  문서의 USD는 API 환산값이다 — 구독에서는 청구가 아니라 Claude 사용 한도 소모로 읽는다.

1. 순서가 공식(턴 × 고정분 + 읽기)에 맞는가, 빠진 지렛대가 있는가.
