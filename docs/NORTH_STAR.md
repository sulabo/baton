## 1. 북극성 한 장

```
USER
 ↓
BATON ── Decision Layer:  Rules(먼저) → Jev(선택, 애매할 때만) → Agent Judge(Claude/Codex, 최후)
 ↓
Context Controller ── Active State(책상 위: 목표·가설·작업 파일·다음 행동)
 │                 └─ Durable State(서랍: Concept Graph · Ontology · Event Log · 옛 결정 · 옛 인계서)
 ↓                         ↓ 필요할 때만 Retrieval
Context Compiler (예산 — 스펙의 예시값: 300줄 · 개념 8개 · 결정 10개)
 ↓
Claude / Codex (구독 CLI 그대로)
 ↓
Ownership / Session change? ── 아니오 → 계속(압축은 native compact)
                             └─ 예 → Handoff ≤ 200줄 → 다음 실행자
```

**BATON이 아닌 것.** Claude Code·Codex·Compact·Memory·Graph·Ontology·Git·MCP를 대체하지 않는다. 그 사이에서 무엇을 읽고 무엇을 안 읽을지, 무엇을 넘길지, 어떤 판단이 규칙으로 충분한지를 정한다.

**핵심 구분 둘.**
- **Compact ≠ Handoff.** Compact는 같은 실행자의 기억 압축(native 기능 사용), Handoff는 다른 실행자에게 상태 전달. Handoff는 연대기 요약이 아니라 **작업 상태 스냅샷**이다.
- **Active ≠ Durable.** 컨텍스트에는 지금 작업의 Working Set만. 나머지는 밖에 두고 필요할 때 가져온다.

**Handoff.** 200줄 hard budget. 우선순위 A(반드시): Goal · Current State · Decisions · Next Action · Blocking Issues · **Do Not Repeat**. B(여유 있으면): Working Files · Test Results · References · Constraints. C(빼기): 작업 로그·전체 코드·diff·git 이력·장황한 추론.
트리거는 크기가 아니라 **실행 주체 변경**(Claude↔Codex, 세션 끝, 단계 완료, 서브에이전트 위임·복귀, 사용자 `/handoff`). 애매하면 Jev.
생성 뒤 **검증**(Goal·Next Action·Do Not Repeat 있나, 200줄 이하, 긴 코드·전체 diff·민감정보 없나).

**Jev.** TypeSafe의 판단 모델. Noul(참/거짓 0~1) · Choice(선택+확률) · Score(루브릭), 한 호출에 여러 질문 병렬.
역할은 **"규칙으로는 애매하지만 Claude/Codex에 맡기기엔 사소한 판단"**뿐 — 도메인 판별, 개념 후보 관련도(스펙 예: ≥0.80 전문 / 0.50~0.79 요약 / <0.50 버림), 스킬 선택, 인계서 필요 여부, 실행기 선택.
**선택 사항이다. Jev 없이 BATON은 정상 작동해야 한다.** 외부로는 메타데이터 먼저(작업 요약·개념·스킬 이름·파일 라벨·정제된 요약·후보 라벨), 원문 코드·비밀·개인정보·민감한 저장소 내용은 가급적 보내지 않는다. 작업당 호출 4회 이하.

**롤아웃.** 정본끼리 조금씩 다르다.
- 스펙 47절: V0 Observe → V1 Context Retrieval → V2 Skill Selection → V3 Structured Handoff → **V4 Jev Hybrid** → V5 Agent Routing.
- 스펙 29절: V0 Observe → V1 Retrieval → V2 Skill → V3 Handoff → **V4 Agent Routing**(Jev 단계 없음).
- Jev 가이드 28절: Phase 0 Baseline → **Phase 1 Jev Shadow Entry** → Phase 2 Retrieval → … (Jev가 처음부터).
- 공통: Observe가 먼저, **Agent Routing은 가장 마지막**(잘못된 실행기 선택은 작업 방향 전체를 틀기 때문).

**성공 조건(스펙 46절 예시).** 컨텍스트 감소 ≥20% · 작업 성공률 하락 ≤2% · 인계서 ≤200줄 · 반복 조사 감소. 못 채우면 그 게이트는 끈다.
구독 사용자의 실제 KPI는 **같은 사용 한도로 끝내는 작업 수**.

**거꾸로 된 곳 넷 (이번 개정의 반전).**
1. **Jev의 뜻이 줄어 있었다.** ROADMAP 6단계는 Jev를 "규칙이 못 가른 요청에서 개념을 고르는 작은 모델"로 적었다. 정본의 Jev는 Decision Layer 2층 — 컨텍스트·스킬·인계서·실행기 판단을 맡는 선택형 판단기다.
2. **6단계 판정 기준이 틀렸다.** 09-30에 "오답 3건 중 맥락 선택 실패 0건 → Jev 착수 근거 없음"이라 썼다. 스펙의 성공 기준은 **성공률 유지 + 컨텍스트 감소**이고, 오답을 고치는 것은 Jev의 일이 아니다. **그 판정은 철회한다.** 코덱스의 도입 조건("같은 미열람 라벨 집합에서 Rules+Jev가 Rules only보다 잘못된 라우팅을 줄이고 비용이 허용 범위")은 취지를 잇되, 사례 모음에 라우팅 라벨이 없어 **잴 수 있는 기준(정답률 유지 + 맥락 감소)으로 바꿨다** — 3절 단계 4의 켜는 조건.
3. **정본의 V0는 아직 없다.** 스펙 47절의 V0는 "BATON이 판단하고 로그만, 실행은 그대로". 코덱스 안은 거기에 Rules 한정·Explain·wrapper 전용을 더했다. 실제로 만든 V0는 과거 기록 채점기였고 닫혔다.
4. **baton은 훅으로 시작했다.** "wrapper 먼저, 훅은 안정화 뒤"는 Jev Control Plane 21~22절과 코덱스 안의 방침이다(63절 스펙에는 훅 언급이 없다). baton은 훅으로 인계서 받는 쪽을 먼저 만들었다. 이유는 09-21 세션 기록에 있다 — **소유자는 `claude`를 먼저 띄우고 그 안에서 지시하므로, 밖에서 감싸는 wrapper는 그 프롬프트를 못 본다.** 3절 설계 선택 1이 이 이탈을 이어 간다.

## 3. 북극성으로 가는 길

> **방향 전환(2026-09-30, 소유자 결정 "세션 끊기 먼저")** — 실사용 세션 60개를 재 보니 비용의 85%(비용 가중)가 맥락이 첫 호출의 2배를 넘은 뒤에 나가고, 초반 5호출은 2.8%였다(`LOOP_PLAN.md` "토큰이 어디로 가나"). 아래 단계 0~2가 겨냥하는 "시작할 때 무엇을 읽힐까"는 이 사용 방식에서 작은 몫이다.
> 그래서 **맨 앞에 "세션 끊기"(단계 S)를 둔다**: 맥락이 불어나면 인계서를 쓰고 새 세션으로 넘긴다 — 정본의 "State should be transferred, not replayed"를 세션 안에서 적용한다. 재계산 추정(비용 0): 문턱 2배·인계서 4K·방향 잡기 3회에서 비용 약 45%, 다시 읽기 2만 토큰을 더하면 약 35% 절감. 인계서로 새로 시작한 실제 세션은 초반 3~10호출에서 다른 세션보다 약 5~9K만 더 읽었다.
> **정본과 충돌하는 곳**: 정본 8절 "Handoff는 Context 크기 때문에 발생하지 않는다". 이 저장소는 소유자 결정으로 크기(맥락 배수)를 **권고** 트리거로 더한다 — 넘길지는 사람이 정한다. Jev의 자리도 여기로 옮겨 온다: 출구 관문 "계속할까, 넘길까?".
> 단계 1(관찰)은 구현돼 있으나 효과 순서로는 뒤다. 단계 2(시작 시 맥락 조립)는 세션 끊기 뒤의 **새 세션 첫 맥락**을 줄이는 쪽으로 다시 본다.

### 단계 S — 세션 끊기 (결정론, 비용 0 — 1순위)

> **상태(10-01)**: `hooks/split-notice.py`를 `hooks.json`의 `Stop`에 등록, 테스트 7개(`hooks/test_split_notice.py`), 실제 세션 기록으로 첫·마지막 맥락 읽기 확인. 실사용 효과는 설치 뒤.

- `Stop` 훅이 턴이 끝날 때 세션 기록에서 호출당 맥락을 읽고, 첫 호출의 2배·3배를 처음 넘을 때 **한 번씩만** 사용자에게 알린다: "여기서 인계서를 쓰고 `/clear` → '이어서'로 넘기면 호출당 맥락이 다시 첫 크기에서 시작한다". 매번 울리지 않는다.
- 넘긴 뒤는 이미 있는 것들이 잇는다: 인계서 스킬(≤200줄, Do Not Repeat) → `/clear` → 상태 프롬프트에 인계서 주입(훅).
- 알림·넘김을 관찰 로그에 남겨 실제 절감(넘긴 세션 대 안 넘긴 세션)과 넘긴 뒤 재작업을 잰다.
- 다음: 끊기 판단을 문턱에서 Jev 출구 관문("작업 덩어리가 끝났나")으로 — 길 단계 4.

**정본에서 벗어나는 선택 넷 — 먼저 밝힌다.** 이 선택들은 소유자 결정(`DECISIONS.md`)의 범위 안에서만 유효하다. 특히 **09-22 소유자 결정 "라벨링 안 함"** — 평가에 사람 라벨·사람 표본을 쓰지 않는다. 정답은 이력에서 뽑는다(09-27 세션 판정, 사례 모음). 09-30 판은 이를 어겨 선택 4·단계 1·3에 사람 표본을 넣었다가 10-01에 정정했다.
1. **훅 먼저**(정본: wrapper 먼저 — Jev Control Plane·코덱스). 이유는 위 2절 4번. V0·V1·V3·V4를 `UserPromptSubmit`·`Stop` 훅에서 한다. 스킬 목록·실행기는 세션을 띄울 때 정해지므로(추론 — 세션 중 스킬 목록을 바꾸는 방법은 확인 못 함) V2·V5는 실행 옵션을 정하는 wrapper에서 한다.
2. **순서 변경.** 스펙 47절 순서 V0→V1→V2→V3→V4→V5를 **V0→V1→V3→V4→(V2·V5를 wrapper 한 단계로)**로 바꾼다. V3(인계서)를 V2(스킬)보다, V4(Jev)를 V2보다 앞에 둔다. 이유: V2는 wrapper가 있어야 하고, V3는 baton의 본업이자 이미 절반이 있다. Agent Routing이 마지막인 것은 그대로다.
3. **Jev가 이겨야 할 기준선을 하나 더.** ① 규칙만 ② **메인 모델이 개념 색인(제목·한 줄·별칭)만 보고 스스로 여는 방식**(추가 호출 0 — Claude Code 스킬 목록과 같은 구조) ③ 규칙 + Jev. ②는 가장 싼 기준선이다. 다만 외부 측정상 기본 자가 선택은 약했다(스킬 활성화 50~55%) — Jev·강제 평가가 이 수치를 넘는지가 관건이다.
4. **행동을 대리 신호로.** "세션이 그 뒤 실제로 연 개념 절·결정·인계서"를 컨텍스트 필요 여부의 **약한 대리 신호**로 쓴다. 약한 이유: 열었다 ≠ 필요했다, 필요했는데 안 연 경우가 있다(5단계 허브 사례), 이미 주입된 것은 다시 열 필요가 없어 신호가 사라진다. 그래서 대리 신호는 보조로만 쓰고, **정답은 이력에서 뽑은 사례 모음**(`observer/research/cases.json`, 행동 기준 채점)으로 잰다. 코덱스는 사람 표본·20% 무작위 사람 감사를 권했으나 09-22 소유자 결정으로 쓰지 않는다. **작업 성공률은 따로 채점**한다.

### 단계 0 — 설치하고 기준선과 비교 (지금, 소유자 설치만 남음)
- 사본으로 설치(`tools/stage-plugin.sh`) → 2주 → 주입된 상태 세션의 첫 5호출 재독률(기준 41/42)·여는 구간 토큰(기준 약 357K~401K) 비교.
- 인계서 받는 쪽 주입이 실사용에서 듣는지의 첫 증거다.

### 단계 1 — V0 Observe + Explain (결정론, 비용 0)

> **상태(09-30)**: 판단·기록·설명 **구현 완료**(`lib/rules.py`, 훅 관찰 로그, `/baton-explain`). 판단 로그를 행동 라벨과 맞춰 재는 부분은 **로그가 쌓인 뒤**(설치 후). 정본과 다른 점: 로그는 저장소별 `.baton/`이 아니라 `~/.cache/baton/runs.jsonl` 한 곳(공개 저장소에 추적 안 된 파일을 만들지 않으려고). 도메인은 UNCONFIGURED로만 낸다. 자세한 것은 `LOOP_PLAN.md` 끝 절.
- 훅 안에 `RulesProvider`: 프롬프트마다 도메인·작업 종류·인계서 필요·후보 개념을 판단하고 결과를 **MATCHED / AMBIGUOUS / NO_MATCH** 셋으로 낸다(규칙 하나만 맞음 / 둘 이상 / 없음).
- **행동은 지금 그대로**, 판단만 `~/.cache/baton/runs.jsonl`에 남긴다(무엇을 넣었나·무엇을 넣을 뻔했나·몇 줄).
- `/baton-explain "…"`으로 "넣을 것 / 요약만 / 버릴 것 / 판단 경로"를 보여 준다(스펙 34절).
- 2주 로그 + 대리 신호로 규칙의 recall·true negative를 어림하고, 대리 신호와 규칙 판단이 갈린 요청은 사례 모음에 넣을 **후보**로만 모은다(정답 확정은 이력에서). AMBIGUOUS·NO_MATCH 비율은 **Jev 후보 표본의 크기**일 뿐이다 — Jev의 가치는 단계 4의 직접 비교로만 판정한다(V0_SPEC 227~228줄).

### 단계 2 — V1 Context Retrieval (결정론, 비용 0)
- **개념 색인**: 개념마다 제목·한 줄·짧은 별칭·이웃. 별칭은 사람이 붙인다(V0의 제안 — "긴 제목을 통째 사전으로 쓰면 적중이 낮다", 입증은 아님). 저장소당 개념 11~35개라 색인 전체가 후보 N이다.
- **GraphProvider.search**: 맞은 개념 + 간선 한 칸 이웃. 공유 파일 동시출현 간선은 만들지 않는다(9개 → 36개 폭발).
- **Context Compiler + Budget**: 인계서에서 Active 부분(목표·다음 행동·Do Not Repeat·막힌 것)만, 고른 개념 절, 관련 결정 — 예산 안에서.
- A/B(스냅샷 러너 + 실사용): 인계서 통째 대 Compiler, 그리고 ② 기준선. 성공 조건은 스펙 46절 예시를 출발점으로, **평가 전에** 합격선을 정한다.

### 단계 3 — V3 Structured Handoff 완성 (결정론, 비용 0)
- **Handoff Validator**: 스펙 26절 항목을 코드로(필수 절·200줄·긴 코드 블록·전체 diff·민감정보 패턴). 스킬이 쓴 뒤 자동으로 돈다.
- **결정론 트리거**: `Stop`·`SessionEnd` 훅에서 "작업 중 파일 변경이 있었고 인계서가 그 뒤로 안 바뀜"이면 인계서를 **제안**(쓰기는 사람 승인). Claude↔Codex 전환 트리거는 wrapper 단계에서.
- **반복 조사율**: 다음 세션이 Do Not Repeat 항목을 다시 했는지 — 의미 대조라 규칙만으로는 다 못 센다. 사람 라벨은 쓰지 않는다(09-22). 행동으로 셀 수 있는 몫(같은 명령·같은 파일을 같은 목적으로 다시 실행)만 세션 기록에서 규칙으로 세고, 나머지는 **"못 셌다"**로 낸다. Jev를 켠 저장소에서는 의미 대조를 Jev 질문으로 더한다 — Jev를 끈 저장소에서도 행동 몫은 그대로 잴 수 있어야 한다.

### 단계 4 — V4 Jev Hybrid (소유자: API 키·예산·보낼 범위 결정 뒤)
- `JevProvider`를 `DecisionProvider` 뒤에. **규칙이 AMBIGUOUS·NO_MATCH일 때만** 한 번 부른다(질문은 한 호출에 묶음). 타임아웃은 훅 한도 안, 실패·낮은 확률이면 규칙 결과대로.
- **평가 집합 = ROADMAP 6단계 원안**: 사례 모음(`cases.json` 20건)의 `evidence`를 정답으로 ①②③을 돌린다. 정답이 이력에서 오므로 이 집합이 코덱스 조건의 "미열람 라벨 집합" 자리다. 오답이 3건뿐이라 "오답을 고치나"가 아니라 **"정답률 유지 + 실은 맥락 감소"**로 판정한다(정본 46절).
- **먼저 Shadow**: Jev 판단은 로그만. 같은 사례 모음에서 ①②③ 비교 — recall·true negative·지연·비용.
- 보내는 것은 메타데이터 먼저. **마스킹 대상 수치를 담은 저장소(문서 저장소 등)는 기본 제외.**
- **켜는 조건(둘 다):** ③이 ①보다 같은 사례 모음에서 정답률을 유지하면서(하락 ≤2%p, 정본 46절 예시 — n=20에서 1건이 5%p라 사실상 정답 감소 0건) 실은 맥락이 줄고(Jev 호출 비용 차감 후), 비용·지연이 사전에 정한 범위 안. 그리고 ③이 ②보다도 낫다. 코덱스 조건의 "잘못된 라우팅 감소"는 사례 모음에 라우팅 라벨이 없어 직접 못 잰다 — 정답률 유지와 맥락 감소로 대신한다. 아니면 끈 채로 둔다 — "Jev 없이도 정상 작동"이 원칙이다.

### 단계 5 — wrapper `baton "task"`: V2 Skill Selection · V5 Agent Routing
- `baton "task"` → Rules/Jev로 스킬 묶음·실행기 결정 → 그 조건(실행 옵션·설정)으로 `claude`/`codex exec`를 띄운다. `--bypass`(스펙 필수), `--explain`·`--agent`.
- 고정분(첫 턴 약 44K 중 플러그인·스킬·MCP 약 11K)을 작업마다 줄이는 길이다. Claude↔Codex 인계서 트리거도 여기서 결정론이 된다.
- 품질 전체를 흔들 수 있어 **마지막**. Agent Routing은 충분한 로그 뒤에만.
