# baton 1.0.1

**Stop your AI agent from re-reading your project every new session.**
baton 1.0.1 changes when the agent saves a handoff at a context threshold (Claude Code): only when there was work since the last handoff, and at 250K and 450K tokens of context instead of 2× and 3× the first call. Handoff writing was also changed to need fewer calls (not measured yet). It also corrects the `/compact` comparison: one of the two repos is left out, so the pre-registered rule gives no verdict ([correction](https://github.com/sulabo/baton/blob/main/docs/research/compact-vs-handoff.md#correction-2026-11-25)).
English overview: [README.md](https://github.com/sulabo/baton#readme) · homepage: https://sulabo.github.io/baton/

AI가 새 대화마다 프로젝트를 처음부터 다시 읽지 않게 하는 Claude Code·Codex 플러그인입니다.
맥락 문턱에서 인계서를 남기는 규칙을 고친 판입니다.

## 설치·업데이트

Claude Code 안에서:

```
/plugin marketplace add sulabo/baton
/plugin install baton@baton
```

이미 설치했다면 터미널에서 `claude plugin marketplace update baton` → `claude plugin update baton@baton`을 돌리고 창을 새로 엽니다. 열려 있던 창은 옛 훅을 계속 씁니다. Codex는 `codex plugin marketplace upgrade baton`.
필요한 것은 `git`과 `python3`뿐입니다. Codex(0.155 이상) 새 설치는 `codex plugin marketplace add sulabo/baton` → `codex plugin add baton@baton`.

## 1.0.1에서 바뀐 것

- **넘길 일이 있을 때만 묻습니다**(Claude Code). 맥락이 문턱을 넘어도, 마지막 인계서 뒤에 한 일이 없으면(질문만 한 턴 등) 인계서를 쓰게 하지도 알리지도 않습니다. 한 일로 세는 것은 `Write`·`Edit`로 고친 파일, 파일을 쓰는 게 분명한 Bash 명령, 맡긴 서브에이전트가 실제로 파일을 고친 경우입니다(서브에이전트 기록을 못 찾으면 Explore·Plan·리뷰처럼 읽기만 하는 종류가 아닌 위임은 셉니다). 그 문턱은 지나간 것으로 치지 않고, 나중에 일한 턴 끝에 한 번 묻습니다.
- **문턱을 호출 맥락 25만·45만 토큰으로 바꿨습니다**(`BATON_SPLIT_TOKENS`, 기본 `250000,450000`). 전에는 첫 호출의 2배·3배였습니다. 새 대화로 넘어가는 쪽이 대개 더 싸다는 문장은 25만 이상 문턱에서만 씁니다. `BATON_SPLIT_RATIOS`만 직접 정해 둔 사람은 예전처럼 첫 호출의 몇 배로 보고 문장도 예전 그대로입니다(넘길 일이 있을 때만 묻는 것은 같습니다).
- **인계서를 쓸 때 드는 호출을 줄이도록 바꿨습니다.** 저장 검사를 통과하면 훅이 한 줄로 알려 검사기를 다시 돌리지 않게 하고, 승격 검토 요약(`promote.sh --brief`)을 git 상태 확인과 한 번에 부릅니다. 이미 확인한 사실은 다시 돌리지 않습니다. 커밋은 `HANDOFF.md`만 합니다(미리 스테이징해 둔 다른 파일이 같이 커밋되지 않습니다).
- `/baton-setup`은 맥락 문턱을 더는 제안하지 않고, 기본값과 그 출처만 보여 줍니다.

**왜 바꿨나.** 1.0.0의 맥락 문턱이 실제 대화에서 처음 울렸을 때, 질문만 한 턴인데도 대화를 멈추고 인계서를 다시 쓰게 했습니다. 또 만든 사람의 대화 50개를 인계서 쓰는 비용까지 넣어 다시 계산하니, 실험에 맞춘 단가로는 첫 호출의 2배(약 15만 토큰)에서 끊으면 대개 손해였습니다. 그 크기에 닿은 대화 중 끊어서 이득 본 비율은 15만에서 24%, 25만에서 64%, 45만에서 60%였습니다(표준 단가 비율로는 더 일찍 이득이 나서, 15만에서 51%). 한 사람의 기록으로 낸 추정이고, 조건과 표는 [docs/research/LOOP_PLAN.md](https://github.com/sulabo/baton/blob/main/docs/research/LOOP_PLAN.md)에 있습니다.

## `/compact` 맞대기 결과 정정

저장소 두 곳 중 하나에서 `/compact` 쪽에도 인계서가 들어가 그 저장소를 뺐습니다. 그러면 미리 정한 판정 규칙(저장소 2곳 이상)으로는 판정을 내릴 수 없습니다. baton 저장소만 보면 `/compact`는 5번 중 5번, 인계서는 쓰는 방식을 고친 뒤 2차에서 5번 중 5번 맞았습니다(2차는 인계서 쪽만 다시 돌려 1차 `/compact`와 비교). 2차 비용은 인계서 쪽이 `/compact`의 약 1.7배였습니다(중앙값, 프롬프트 캐시가 살아 있다고 쳤을 때. 보고된 비용 그대로는 1.2배). 자세히: [정정 절](https://github.com/sulabo/baton/blob/main/docs/research/compact-vs-handoff.md#correction-2026-11-25).

## 아직 확인하지 못한 것

- **인계서 쓰기가 실제로 싸졌는지는 아직 재지 않았습니다.** 전에는 compact 맞대기 실험 2차(약 22만–24만 토큰 대화)에서 한 번 쓰는 데 호출 중앙값 6번, 저장소별 중앙값 $0.65–0.73(프롬프트 캐시가 살아 있다고 쳤을 때)이었습니다. 이 판으로 다시 잴 예정입니다.
- **"넘길 일이 있을 때만" 규칙은 테스트로만 확인했습니다.** 실제 대화에서 울린 기록은 아직 없습니다.
- 맥락 창이 20만 토큰이면 25만에 닿기 전에 압축되어 이 규칙이 울리지 않습니다. 문턱을 낮출 수는 있지만, 그 크기에서 새로 시작하는 쪽이 더 싼지는 재지 않았습니다.
- 실사용에서 토큰이 줄었는지는 아직 모릅니다.

## 알려진 한계

- 수치는 만든 사람 한 명의 기록에서 나왔습니다.
- 인계서가 없는 저장소에서도 `HANDOFF.md`를 새로 만듭니다(이 대화에서 한 일이 있고 맥락이 문턱을 넘을 때, 또는 파일을 3개 이상 고쳤을 때). 원하지 않으면 `BATON_HANDOFF_AUTO=off`(쓰지 않고 알리기만). 맥락 문턱만 끄려면 `BATON_SPLIT_NOTICE=off`.
- 자동 갱신, 맥락 문턱 인계서 갱신, 저장할 때 자동 검사는 Claude Code에서만 돕니다.
- 인계서를 넣는 말은 프롬프트 어디에 있어도 걸립니다. 붙여 넣은 글 속의 "이어서"에도 인계서가 들어갑니다.
- 플러그인이 띄어쓰기가 있는 경로에 설치되면 스킬이 스크립트를 실행하지 못할 수 있습니다(기본 설치 경로에는 없습니다).
- 인계서 검사기는 일부 비밀값 형식(`postgres://user:pw@host`, `npm_`·`hf_` 토큰, JWT가 아닌 Bearer 값)을 놓칩니다.
- `/rewind` 뒤에는 인계서가 맥락에 있다고 보고 다시 넣지 않습니다.
