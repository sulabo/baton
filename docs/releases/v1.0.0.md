# baton 1.0.0

**Stop your AI agent from re-reading your project every new session.**
baton 1.0.0 is the first stable release. It has the same features as 1.0.0-beta.5: handoffs that tell the next session what to do, not what to ask, and a handoff saved when the conversation passes 2× and 3× its first size (Claude Code). baton doesn't suggest `/compact`.
English overview: [README.md](https://github.com/sulabo/baton#readme) · homepage: https://sulabo.github.io/baton/

AI가 새 대화마다 프로젝트를 처음부터 다시 읽지 않게 하는 Claude Code·Codex 플러그인입니다.
첫 정식판입니다. 기능은 1.0.0-beta.5와 같습니다.

## 30초 설치

Claude Code 안에서:

```
/plugin marketplace add sulabo/baton
/plugin install baton@baton
```

이미 설치했다면 터미널에서 `claude plugin marketplace update baton` → `claude plugin update baton@baton`을 돌리고 창을 새로 엽니다. 열려 있던 창은 옛 훅을 계속 씁니다. Codex는 `codex plugin marketplace upgrade baton`.
필요한 것은 `git`과 `python3`뿐입니다. Codex(0.155 이상)는 `codex plugin marketplace add sulabo/baton` → `codex plugin add baton@baton`.

## 1.0.0에 들어 있는 것

- **인계서(`HANDOFF.md`).** 하던 일을 한 장으로 남기고, 새 대화에서 "이어서"라고 하면 그 한 장과 작성일·그 뒤 커밋 수를 함께 넣습니다. 저장할 때 형식·비밀값·빠진 줄을 검사합니다.
- **바로 이어 가는 다음 행동.** 다음 행동은 묻지 않고 실행할 수 있게 쓰고, 정말 사람이 정할 것은 `소유자 확인` 목록에 추천안과 되돌릴 수 있는지를 함께 적습니다.
- **알아서 남기는 인계서**(Claude Code, 기본 켬). 파일을 3개 이상 고쳤을 때, 그리고 맥락이 첫 호출의 2배·3배를 넘을 때 에이전트가 `HANDOFF.md`를 갱신하고 한 줄로 알립니다. 끄기: `BATON_HANDOFF_AUTO=off`(알림만), `BATON_HANDOFF_NUDGE=off`(파일 수 규칙), `BATON_SPLIT_NOTICE=off`(맥락 규칙).
- **개념 지도(`CONCEPTS.md`).** 프로젝트의 핵심 개념을 결정·코드·문서와 묶고, 바뀐 파일에 걸린 개념만 다시 보게 합니다(`/drift`).
- **결정 기록(`DECISIONS.md`)**, 승격 검토(`/promote`), 설치 점검(`/baton-doctor`), 개인 문턱 제안(`/baton-setup`). 한국어·영어 화면.

**왜 바꿨나.** `/compact`로 이어 가기와 인계서로 새로 시작하기를 맞대 보는 실험을 하고 있습니다. 1차에서 인계서 쪽이 실패한 경우는 모두, 새 대화가 인계서에 적힌 "사용자에게 확인할 것"을 묻고 아무것도 고치지 않은 채 멈춘 경우였습니다. 그래서 인계서 쓰는 방식을 먼저 고쳤습니다. 결과 수치는 고친 뒤 다시 재서 함께 공개합니다.

## 아직 확인하지 못한 것

- **beta.5의 인계서 개선 효과는 아직 다시 재는 중입니다.** 같은 조건으로 인계서 쪽만 다시 잴 예정이고, 1·2차 결과를 조건과 함께 공개합니다. 그 전에는 "`/compact`보다 낫다"거나 "싸다"고 말하지 않습니다.
- **인계서를 쓰는 비용은 이번 판에서 줄지 않았습니다.** 긴 대화의 맥락을 다시 읽고 써야 하기 때문입니다.
- **맥락 문턱에서 인계서를 쓰는 동작은 실제 대화에서 써 본 기록이 없습니다.** 테스트로만 확인했습니다.
- 실사용에서 토큰이 줄었는지는 아직 모릅니다.

## 알려진 한계

- 수치는 만든 사람 한 명의 기록에서 나왔습니다.
- 인계서가 없는 저장소에서도 맥락이 2배를 넘으면 `HANDOFF.md`를 새로 만듭니다(파일을 고치지 않았어도). 원하지 않으면 `BATON_SPLIT_NOTICE=off`.
- 자동 갱신, 맥락 문턱 인계서 갱신, 저장할 때 자동 검사는 Claude Code에서만 돕니다.
- 인계서를 넣는 말은 프롬프트 어디에 있어도 걸립니다. 붙여 넣은 글 속의 "이어서"에도 인계서가 들어갑니다.
- 플러그인이 띄어쓰기가 있는 경로에 설치되면 스킬이 스크립트를 실행하지 못할 수 있습니다(기본 설치 경로에는 없습니다).
- 인계서 검사기는 일부 비밀값 형식(`postgres://user:pw@host`, `npm_`·`hf_` 토큰, JWT가 아닌 Bearer 값)을 놓칩니다.
- `/rewind` 뒤에는 인계서가 맥락에 있다고 보고 다시 넣지 않습니다.
