# baton 1.0.3

**Stop your AI agent from re-reading your project every new session.**
baton 1.0.3 makes writing a handoff take two fewer model calls: the skill fills in the repo state when it loads, and the agent saves and commits in one response. The commit runs only after the checker passes, so a secret or a home path never reaches git history. Measured against 1.0.1 (2 repos × 5 writes), calls fell from 5 to 3 and from 6 to 4, but the cost per write fell only 5–7%, short of the pre-registered 10%, so it is not claimed as cheaper. The dropped-lines warning now looks only at the sections meant to carry over, after two independent labelings found 61–63% of its warnings were false. A new homepage section shows one word mark per skill and command.
English overview: [README.md](https://github.com/sulabo/baton#readme) · homepage: https://sulabo.github.io/baton/

AI가 새 대화마다 프로젝트를 처음부터 다시 읽지 않게 하는 Claude Code·Codex 플러그인입니다.
1.0.2 뒤에 남은 구멍을 막고 인계서 쓰는 호출을 줄인 판입니다.

## 설치·업데이트

Claude Code 안에서:

```
/plugin marketplace add sulabo/baton
/plugin install baton@baton
```

이미 설치했다면 터미널에서 `claude plugin marketplace update baton` → `claude plugin update baton@baton`을 돌리고 창을 새로 엽니다. 열려 있던 창은 옛 훅을 계속 씁니다. Codex는 `codex plugin marketplace upgrade baton`.
필요한 것은 `git`과 `python3`뿐입니다. Codex(0.155 이상) 새 설치는 `codex plugin marketplace add sulabo/baton` → `codex plugin add baton@baton`.

## 1.0.3에서 바뀐 것

- **인계서 쓰는 호출이 두 번 줄었습니다**(Claude Code).
  - 스킬을 불러올 때 저장소 상태(`git status`·`git log`)와 승격 검토 요약이 미리 채워집니다. 그래서 쓰기 전에 따로 확인하는 호출이 없습니다.
  - 인계서 저장과 커밋을 한 응답에서 합니다.
  - 스킬 본문은 24.7KB에서 12KB 아래로 줄였습니다. 까닭과 측정은 같은 폴더의 `REFERENCE.md`로 옮겼고, 지시는 빼지 않았습니다.
- **검사를 통과해야만 커밋합니다.** 커밋 명령 앞에 검사기가 붙어 있어서, 문제가 있으면 아무것도 커밋하지 않습니다. 비밀값·홈 폴더 경로·개인 자료 단어가 git 기록에 남지 않고, 크기 상한을 넘은 인계서도 줄일 때까지 커밋하지 않습니다. 저장 검사가 돌지 않는 Codex에서도 같은 검사기가 커밋을 막습니다.
- **빠진 줄 경고가 줄었습니다.** 이어 가야 하는 절(실패한 접근법·승격 후보·기각됨)만 봅니다.
  - 까닭: 한 저장소의 인계서 기록(커밋 20개, 경고 128건)을 두 사람이 따로 분류해 보니(127건 중 121건 일치) 61–63%가 헛경고였습니다. 끝난 일을 지운 것을 두고 울린 경우가 대부분이었고, 경고가 "되살려라"라고 해서 AI가 끝난 일을 다시 적게 만들 수 있었습니다.
  - 남은 절에서도 헛경고는 44–45%입니다.
  - 대신 두 사람이 모두 진짜라고 본 4건은 더는 잡지 못합니다.
  - 전에 공개한 "오탐 약 20%"(20줄 표본)는 틀렸습니다.
- **질문만 한 턴은 여전히 멈추지 않습니다**(Claude Code). 뒤에서 돈 서브에이전트가 고친 것도 맥락 문턱의 "한 일"로 셉니다. 다만 그 완료 알림이 질문 턴 중에 들어오면, 다음에 일한 턴까지 미뤄 셉니다.
- 서브에이전트 안에서 Bash로 쓴 `HANDOFF.md`도 그 호출이 시작된 시각을 찾아, 다른 창이 바꾼 것을 잘못 검사하지 않습니다.
- 30일 넘게 열어 둔 창이 저장 검사 기억을 잃지 않습니다.
- 0건 가드는 `lib/` 폴더의 검사 스크립트를 돌렸을 때만 봅니다.
- 홈페이지에 "baton에 든 일곱 가지" 절이 생겼습니다. 스킬·명령마다 한 단어 로고와, 하는 일·부르는 법을 한 줄씩 보여 줍니다.

## 잰 것

1.0.1의 인계서 쓰기를 잰 것과 같은 긴 대화(22만–25만 토큰)에서, 미리 정한 규칙대로 쟀습니다(2026-11-26, 저장소 2곳 × 5번, opus 5.5).

| | 1.0.1 | 1.0.3 |
|---|---|---|
| 쓰기 한 번의 호출(baton 저장소) | 5번 | **3번** |
| 쓰기 한 번의 호출(다른 저장소) | 6번(5–8) | **4번** |
| 쓰기 한 번의 비용, 중앙값(baton 저장소) | $0.670 | $0.625 |
| 쓰기 한 번의 비용, 중앙값(다른 저장소) | $0.570 | $0.541 |
| 필요한 사실을 지킨 인계서 | 10개 중 9개 | 10개 중 9개 |

- 비용은 5–7% 줄었지만, 미리 정한 기준(두 저장소 모두 10% 넘게)에 못 미쳐 **"싸졌다고 보이지 못함"**으로 판정했습니다.
- 대화를 다시 읽는 비용은 한 번에 약 9–10센트 줄었습니다. 대신 출력 비용이 약 3–6센트 늘었습니다. 늘어난 출력은 대부분 보이는 글이 아니라 보이지 않는 생각(thinking)으로 보이고, 원인은 재지 않았습니다.
- 비용은 프롬프트 캐시가 살아 있다고 쳤을 때입니다.
- 사전 등록과 결과: `docs/research/handoff-write-w2.md`.

## 아직 확인하지 못한 것

- Codex에서 새 쓰기 흐름이 도는지는 실제 세션으로 보지 못했습니다. Codex는 스킬의 주입 줄을 글자 그대로 보여 주므로 AI가 그 명령을 한 번 돌리고, 검사기 경로의 변수가 비어 있으면 스킬 파일 두 단계 위 폴더를 쓰라고 스킬이 안내합니다.
- 다음 대화가 인계서로 더 잘 이어 가는지는 이번에 재지 않았습니다.
- 실사용에서 토큰이 줄었는지는 아직 모릅니다.

## 알려진 한계

- 수치는 만든 사람 한 명의 기록과, 미리 짠 대화 두 개에서 나왔습니다.
- 저장 자체가 실패해도(예: AI가 읽은 뒤 파일이 바뀜) 같은 응답의 검사-커밋 명령은 디스크에 있는 `HANDOFF.md`를 검사를 통과하면 그대로 커밋합니다.
- 0건 가드는 저장소 자체의 `lib/check.sh`에도 울리고, `cd <플러그인>/lib && ./fresh.sh`처럼 폴더를 옮겨 돌린 경우는 놓칩니다.
- 자동 갱신, 맥락 문턱 인계서 갱신, 저장할 때 자동 검사는 Claude Code에서만 돕니다.
- 인계서를 넣는 말은 프롬프트 어디에 있어도 걸립니다. 붙여 넣은 글 속의 "이어서"에도 인계서가 들어갑니다.
- 인계서 검사기는 일부 비밀값 형식(`postgres://user:pw@host`, `npm_`·`hf_` 토큰, JWT가 아닌 Bearer 값)을 놓칩니다.
